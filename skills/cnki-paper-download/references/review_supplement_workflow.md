# 用已入库文献补充基金申报综述（2026.8.7 实战验证）

少帅已建成文献矩阵库（如《市场化环境治理研究文献矩阵库》30篇），当自科基金申报综述缺中文文献支撑时，按此流程从矩阵库筛选补充，而非重新全网检索。

## 典型场景

- 基金申报综述的参考文献全是英文（OpenAlex/Crossref 导入），中文 CSSCI 为 0
- 少帅说"看看XX文献综述如何补充中文文献，相关的有意义的才补充进去"

## 流程

### 0. 确认目标综述（⚠️ 先问清楚再动手）

少帅可能同时有多个基金申报材料，先确认要补充的是哪个：
- `碳排放权交易文献综述_ABM方法论_改进版.md` — 自科基金用，ABM方法论综述（选题：碳交易机制设计、行为基础与省级市场模拟）
- `湖南省自科基金申报书_交通出行权交易.md` — 申报书本体（TTC借鉴碳排放权理念，需要的是排放权交易文献支撑立项依据）
- 两者都在 `ObsidianVault\academia\` 下，**名字相似易混淆，动手前先读文件确认目标和章节结构**

### 1. 读综述，映射章节需求

读目标综述，列出每个章节的论点 → 需要的文献类型（如：第5章中国碳市场发展需要减排效应/市场一体化/价格联动实证）。

### 2. 从矩阵库提取全部文献元数据

```python
# 解析矩阵库主矩阵表格（| 19 | 排污权交易 | 作者 | 年份 | 标题 | 期刊 | 卷期 | 级别 | 方法 | 结论 | 主题 |）
# 逐行 split("|")，cells[0]=序号, cells[2]=作者, cells[3]=年份, cells[4]=标题,
# cells[5]=期刊, cells[6]=卷期, cells[7]=级别, cells[8]=方法, cells[9]=结论, cells[10]=主题
```

### 3. 逐篇评估价值（高/中/低）

对每篇文献按"方法+主题是否直接支撑综述某章论点"打分：
- **高**：方法/主题与综述某章论点直接相关（如DID类→方法比较章节；企业行为类→研究空白章节）
- **中**：间接支撑（如省级差异→省级特征章节）
- **低**：与综述核心（机制设计/行为/方法）关联弱 → **排除，不凑数**

**筛选原则（少帅原话"相关的有意义的才补充"）**：宁缺毋滥，关联弱的排除。法学监管类/税务会计类与机制设计-行为-ABM主线无关时直接排除。

### 4. 追加 GB/T 7714 参考文献

- 原综述参考文献编号可能不止清单可见数（可能有[35]在280行之外）——**先数清已有条数**再续号
- 格式：`[36] 作者1, 作者2. 标题[J]. 期刊, 年, 卷(期): 页码.`
- 作者之间用逗号，不用"和"；知网文件名连写的作者名（`刘静一朱正康`）需拆分成 `刘静一, 朱正康`

### 5. 正文插入引用标注

- 在对应论点处插入"作者[编号]"标注，**编号前无空格**（GB/T 7714 顺序编码制）：`马彦瑞[36] 基于省域面板数据...`
- 引用内容需与文献实际结论一致（先读矩阵库的"结论"列再写）
- 正文句子保持完整（写入后验证无截断）

### 6. 更新数据完整性声明

综述头部/尾部的 `📊 数据完整性声明` 需更新：
- 日期改为当天
- "未获取：中文核心期刊文献" → 标注"中文核心期刊文献13篇（[36]-[48]，CSSCI来源）已获取"
- 注意：**学术交付物中不要出现"少帅"等非正式称呼**（内部文件可以，但要正式化表述如"均来自已建成的文献矩阵库"）

### 7. 验证（硬验证清单）

```python
# 1. 13篇编号在正文均出现（split("## 参考文献")[0] 中搜索 [N]）
# 2. 参考文献总数 = 原数 + 新增数
# 3. 中文条目数 = 新增数
# 4. 编号连续 1..N（无断号）
# 5. 正文引用无空格格式（正则 r'[\u4e00-\u9fff]{2,6} \[(3[6-9]|4[0-8])\]' 应为 0 处）
# 6. 数据声明日期已更新
# 7. 新增段落关键句完整（防截断误判）
```

## 陷阱

- **f-string 反斜杠**：Python 3.11 中 `re.search(r'[\u4e00-\u9fff]', ...)` 不能直接写在 f-string 里，先编译 `cn_pattern = re.compile(r'[\u4e00-\u9fff]')` 再用
- **验证器截断误判**：cross_model_verify 传 content 会截断（4000字符内），验证器可能报"句子不完整"——用 read_file 实查确认是否真截断，正文 400 字符截断片段不能作为证据
- **原稿问题不归本次修改**：OpenAlex 导入的英文文献[30][31]缺作者是原稿遗留，本次不修；只修本次新增内容的问题
- **跨子方向借鉴**：排污权交易与碳交易同属污染品交易权，方法（DID/PSM-DID/波特效应检验）和机制设计经验可互相迁移——筛选时不要只盯着同一子方向

## 交叉验证 API 降级链（2026.8.7 实测）

`cross_model_verify` 的可用 API 实测顺序：
1. dashscope/qwen3.7-flash — **403 Forbidden**（文本模型也403，不只是视觉）
2. moonshot/moonshot-v1-8k — **429 Too Many Requests**（限流）
3. deepseek/deepseek-chat — **✅ 成功兜底**

**规则**：验证失败不要跳过第一层，按 dashscope → moonshot → deepseek 顺序逐个换 API 重试。DeepSeek 是最可靠的兜底。
