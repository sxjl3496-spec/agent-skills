# CI-Fix-Loop（CI 故障修复闭环）

## 流程（五步）

1. **读失败**：获取 CI 日志/测试输出（运行复现命令），不凭猜
2. **定位根因**：从第一条错误向上找根因（错误链顶端），区分"表象错误"与"根因错误"——无根因不修复
3. **修复**：最小改动原则——只改根因相关代码，不顺手重构
4. **重新验证**：重跑完整验证（同一命令），证据门控通过才声明修复
5. **报告**：根因→修复→验证结果（含输出引用）

## 高频根因模式

| 症状 | 常见根因 |
|---|---|
| 构建失败 | 依赖版本漂移/路径大小写（Windows 敏感） |
| 测试偶发失败 | 随机种子未固定/时序依赖/浮点比较 |
| 编码错误 | GBK/UTF-8 混用（Windows 中文环境高发） |
| 环境差异 | 本机 vs CI 环境变量/解释器版本 |

## 反模式

- ❌ 修表象（加 try/except 吞错误）不修根因
- ❌ 不重跑验证就声称"修好了"
- ❌ 一次改多处（无法定位哪处生效）

## 实战案例（本团队）

Web 应用数据修复脚本 `fix_data.py`：跨行字符串被 heredoc 转义破坏（SyntaxError）——根因为写入时 `\n` 被转成真实换行；三次修补失败后改用 Write 工具整体重写（最小改动失败→整体重建成功），语法验证通过后重跑处理。
