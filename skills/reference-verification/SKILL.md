# 参考文献真实性核实（Reference Verification）

## 何时使用

- 申报书/论文/综述的参考文献需要逐条验证真实性、补全卷期页码
- 收到含"待核实"标注或"标题+期刊+年份"简化条目的文献列表
- 用户/审稿人指出"引用有残缺""格式不标准"（重大学术问题）
- 任何要写进正式文档的参考文献入库前

## 核心原则（用户 2026.8.7 红线）

0. **分工铁律（用户原话）**："文献这一块的活，你不能交出去给其它agent，你有全面的技能，其它agent没有，你的学术技能最完善。文献这一块的活，你不能分配出去，你得自己把握住"——参考文献核实/整理/格式规范化**必须由具备学术技能的主导 agent 亲自执行**，不外包给辅助队友。辅助队友可做检索初筛/查缺，但最终逐条核实、替换决策、编号联动校验必须主导者亲手做。团队模式下这条同样适用（lead 亲办，不派给双辅）。
1. **参考文献必须真实、GB/T 7714 国标格式、不能有信息残缺**——"待核实"标注、缺失卷期页码、编造条目一律不允许留在最终版
2. **不编造**：查不到就替换为可查证文献，或用"网络首发"等合规标注，绝不凭感觉补数字
3. **AI 辅助生成/辅助 agent 补写的元数据不可信**：实测 18 篇中文文献中 16 篇的卷期页码是编造的（曹辰编成 1-12 实际 165-173、张杨编成 79-92 实际 129-138、[52]编成 52(8):45-50 实际是增刊 15-18）
4. **综述英文条目的 OpenAlex 元数据存在系统性标题失真**——不能直接采信

## 英文文献核实（Crossref，最可靠）

```python
import requests
session = requests.Session()
session.trust_env = False  # 必须绕过系统代理

# 方式1：按标题+作者检索（推荐）
r = session.get("https://api.crossref.org/works", params={
    "query.bibliographic": title_kw,
    "query.author": author,
    "rows": 2,
    "select": "DOI,title,author,container-title,volume,issue,page,published",
}, timeout=25)

# 方式2：DOI 反查（验证已知 DOI 是否真实）
r = session.get(f"https://api.crossref.org/works/{doi}", timeout=20)
```

**判定**：
- 完全一致（标题/作者/刊名/卷期页码）→ 确认
- 标题/期刊/年份不符 → 用 Crossref 结果修正（实测发现：[20]卷号89→92、[25]Technovation 2021,109→2022,110、[26]EIA Review卷号102→99+作者名、[34]页码159-175→404-417+补第四作者）
- **查无此文（多次检索无匹配）→ 疑似编造，必须替换**为 Crossref 可查证的真实同主题文献（实测 7 篇被替换：原 [10][12][13][14][15][16][17] 均查无此文）
- 经典文献（Coase 1960、Kahneman-Tversky 1979、Simon 1955 等）Crossref 收录不全 → 用公认标准信息（[1] Coase, JLE, 1960, 3: 1-44 等），不判为编造
- **作者名一律以 Crossref `family` 字段为准**（2026.8.7 教训）：替换文献时凭 WebSearch 摘要推断作者名会出错——太尉把 Yan&Yuan 推断成"Zhou&Zhao"（搜索摘要显示"Zhou Yan and Zhao Yuan"，按西方名序误解）。**搜索结果仅作线索，不作文档依据**；替换文献的作者名同样必须 Crossref 复核

**替换后**：正文引用编号保持连续（替换不删号），正文引用表述需与新文献主题匹配（如原引"EU ETS交易行为"位置换 Lehmann & Schleich 2025 内部交易实证，契合）。

**⚠️ 作者-年份制文档的替换陷阱（2026.8.7 实战踩坑）**：部分综述底稿（如文献综述主稿）正文用**作者-年份制**引用（"Tesfatsion [2006]"、"Park等[2023]"），不是顺序编码制。此时**不能按编号对齐替换**——直接把申报书 V4.0 条目按编号覆写会错位（主稿[20]是 Park LLM 论文，被覆写成 Fang&Ma 后，正文"Park等[2023]"失去对应条目）。处理：①替换前先扫描正文引用模式（`re.findall(r"([A-Z][a-z]+(?:等)?)\s*\[(20\d{2})\]"`）②作者-年份制文档按**作者+年份匹配**替换，编号仅作参考③被挤出的特殊条目（如 LLM 预印本）追加到列表尾部保留编号④替换后逐条验证正文作者-年份引用能在列表找到对应文献。

## 中文文献核实（真实 PDF 元数据提取，PyMuPDF）

知识库/下载的 PDF 是权威来源。用 `fitz`（PyMuPDF）提取：

1. **刊名/卷期**：首页文本找 `第X卷第X期`、`Vol.X No.X`、刊名行（含"学报/评论/研究/经济"等且含"第/Vol/No/20XX"）
2. **页码——6种实测格式**：
   | 格式 | 识别方法 | 案例 |
   |:---|:---|:---|
   | `·N·`标记 | 正则 `·\s*(\d+)\s*·` 首页+末页 | 马彦瑞 24→32 |
   | 页脚数字 | words 坐标 y > 页面高-70 | 沈子夏 110-127（18页连续） |
   | **反序数字** | "个 十 百"倒序显示（`７ １ １`=117） | 杨志安 116-124 |
   | 页眉页码 | 次页首部"３２ 管理评论"=32起 | 李治国 32-44 |
   | 文章编号 | "1004-8308（2024）01-0040-13"=40页起13页 | 李颖 40-52 |
   | 引用格式行 | PDF内"引用格式：作者. 题名[J]. 刊名, 年, 卷(期): 页码." | 何艳秋 2681-2694 |
3. **末页推算**：首页页码 + PDF页数 - 1
4. **刊名陷阱**：PDF 首页可能显示与文件名不同的期刊（[37]文件名"系统工程理论与实践"但首页是"管理评论"、[49]申报书写"中国人口·资源与环境"但 PDF 是"上海大学学报(社科版)"）——**以 PDF 实际显示为准**
5. 无页码的 2026 新刊 → 查是否为网络首发（PDF 内搜"网络首发"），是则用 `[J/OL]` + 网络首发合规标注

## 反爬渠道清单（直接放弃，别浪费时间）

实测全部失效：CNKI 直连（kns8s/brief/grid 无完整 cookie 返回空）、百度学术（JS渲染）、万方（乱码）、Bing/Google（无页码结果）、中文 DOI 联盟（chndoi.org 无题录）。**唯一可靠路径：PDF 原文提取 + Crossref（英文）**。知网镜像（wxy88.top）检索可用但消耗每日下载额度，且需 Playwright 全流程，为 1-2 篇页码不值得。

## 多文档协同战役管理（2026.8.7 省自科+论文实战沉淀）

用户钦定的长期战役（申报书/综述/主题论文三文档并行）运作规范：

1. **能力矩阵管理**（用户批评"你没有制作一个管理表格"）：建立《团队科研能力矩阵》（`ObsidianVault/🤖 AI Agent/团队科研能力矩阵.md`）——每位 agent 的能力打分（Crossref/PDF提取/GB7714/综述写作/长文写作/审核/代码）、任务-能力匹配表（首选/次选/理由）、已知短板与防范（血泪教训表）。任务分配前查矩阵。**文献类任务必须主导 agent 亲办**（用户钦定），辅助队友只做检索初筛。
2. **丞相亲自把关**（用户原话："你不能当甩手掌柜……你才是最终质量把控者，你也需要亲自上阵的"）：队友写作+队友审核之外，主导者必须：①亲自通读每份交付物全文（不只看队友转述/评分——实测每轮通读都抓出队友漏检问题）②独立终审出自己的问题清单③亲自参与写作（起草润色版/执笔关键段落——Abstract/Conclusion/政策段由主导者执笔质量显著提升）④终审对照权威基准版逐条核对（防旧值回归）
3. **多文档流程链**（用户钦定）：队友写作 → 御史大夫审核（一票否决+评分卡）→ **主导者终审**（独立通读+对照基准版+抽查验证）→ **双评委独立判定**（OpenCode+Aion CLI，CSSCI 投稿标准，客观严格+理由+逐条建议）→ 主导者综合判断评委意见（P0 投稿必需全采纳；格式性/口径差异甄别——如中文 CSSCI 要求的 8000 字/中文摘要对英文 Energies 投稿不适用，明确说明不采纳理由）→ 修改 → 再复核 → 迭代至目标分（95+）
4. **双评委口径差异识别**：御史大夫学术质量分（97）vs OpenCode CSSCI 格式分（85.4）可能差 12 分——原因是评审口径不同（学术质量 vs 中文期刊格式要求）。不要困惑于分数差，分别处理：质量项采纳，格式项判断目标期刊是否要求
5. **图件/实验数据同样交叉核对**：Figure 混入早期数据（基准线 0.90 vs 0.86）、单种子路径代表性不足（改 30 种子平均±95%CI）都是实测抓出的真问题；论文中带 "verified/confirmed" 声称的数值必须从原始数据 JSON/CSV 实测复核（"minimum 1.66"声称 vs 实测 1.6546——见陷阱12）

## 五方联合审核流程（2026.8.7 假文献危机后的标准动作）

单 agent 审核必漏（实测：御史大夫漏 GB/T 7714 卷期页码、太尉漏[14]作者名、OpenCode 综述 13 重复+7 编造+15 错位）。关键文档（申报书/论文/综述）必须**多 agent 独立审核 + 交叉验证**：
1. **分工**：每方审核一个对象（如太尉审申报书、御史大夫审综述论文、OpenCode 审综述主稿、Aion CLI 交叉抽查、主导者全量核实+汇总裁决）
2. **审核标准统一**：全员先读《科研文献规范技能包》（10项检查清单），避免各审各的标准
3. **汇总裁决书**：汇总各方发现→交叉验证（同一问题多方确认=实锤；单方发现=复核）→裁决（通过/有条件通过/不通过）→注明未回收方
4. **同文件不同 agent 审核前必须同步最新副本**（教训：御史大夫读旧副本判"未修正"，实为文件未重新同步）
5. 每轮交叉审核都会抓出新问题（[14]作者名、综述中文页码未同步、±1页码争议）——**多轮不是浪费，是必要**
6. **图件/结果类交付物同样纳入交叉核对**（2026.8.7）：图件数据必须与最终实验记录（Section编号/关键参数）一致——实测 Figure2 混入早期10种子数据（基准线0.90价格触底）被审出，与正式30种子实验（基准线0.86均价47.3）不符。多图统一数据来源，参数调优后必须重新生成全部相关图件；单种子路径代表性不足时改用 30 种子平均±95%CI
7. **实验数据不可信时主动作废**（2026.8.7 Morris 敏感性案例）：实验发现 bug 导致结果不可信（参数注入只实现 2/6 个、5/6 参数效应≈0）时——主动作废结果、定位根因（参数写死未参数化）、修复后重跑，是科研诚信正示范；绝不将就发布。修复后结果有机制发现价值（如收紧率 μ*=0 说明其影响价格水平而非交易量分布）可作论文讨论点

## GB/T 7714-2015 完整性规则

- 期刊：[J] 作者. 题名[J]. 刊名, 年, 卷(期): 页码. （无卷号期刊省略卷：`年(期): 页码`）
- 专著：[M] 作者. 书名[M]. 出版地: 出版社, 年.
- 书章节：[M]//书名. 出版地: 出版社, 年: 页码.
- 报告：[R] 作者. 题名[R]. 出版地: 机构, 年.
- 会议：[C] 作者. 题名[C]//会议录名. 地点, 年: 页码.
- 电子/网络首发：[J/OL] ... [引用日期]. 路径.
- 英文作者：姓全大写+名首字母（COASE R H / FARMER J D），3-6作者全列，超过用", et al."
- **顺序编码制编号顺序**：编号按正文首次引用先后排列——正文先出现 [3] 后出现 [2] 即违规（实测申报书 2.2.1 的 [3]Dales 先于 [2]Montgomery，属格式瑕疵，评审可能挑刺）。文献终审时顺带检查引用顺序，不匹配时提示主导者决定是否重排编号

## 交付标准与校验

1. **零"待核实"、零残缺**——每篇 作者/标题/刊名/年/卷(期)/页码 齐全且可查证
2. **编号完整性脚本**：列表编号与正文引用编号一一对应（正则提取 `^\[(\d+)\]` 和正文 `\[(\d+[-,]\d+)*\]`，求差集）
3. 输出：核实报告（原条目 vs 核实结果 vs 判定：确认/修正/替换）+ 最终列表

## 陷阱

1. **辅助 agent 编造元数据**（最坑）：让队友"补全卷期页码"时，它们可能编造看起来合理的数字。核实前先怀疑一切非 PDF/Crossref 来源的页码
2. **反斜杠转义**：python heredoc 里写 Windows 路径 `\a` 会被解析成 BEL 控制符——路径用正斜杠或 raw string
3. **f-string 反斜杠**：`f"{'ok' if '\\"' in x else 'no'}"` 语法错误——先算变量再格式化
4. **正文-列表对应**：替换文献后正文引用编号必须同步校验；删文献（如合并删1篇）后所有后续编号前移
5. **"查不到"≠"不存在"**：先换检索词（标题精确/作者+主题词），3次以上无匹配才判定编造
6. **"列表未引"策略决策**（2026-08-07 裁决）：GB/T 7714 顺序编码制严格是"列表=正文引用"，但申报书可**策略性保留完整文献库**（如51篇列表仅27处正文引用）以展示文献功底——评审通常不挑刺且是加分项。是否严格删至仅引用数由主导者裁决，倾向保留
7. **±1页码争议裁决**：多轮人工修正后易出现 ±1 页差异（AI 提取起始页误差）——**以 PDF 页码序列（连续段）为准**，不采信人工推算值
8. **五方交叉审核抓漏**：单 agent 审核会漏（御史大夫漏卷期页码、太尉漏[14]作者名、OpenCode 综述引用错位）——关键文档用多 agent 独立审核+交叉验证，每轮都能抓出新问题
9. **引用语境与文献主题不匹配**（综述审核 4 例实测，2026.8.7）：文献真实≠引用正确——编号所在句子的主题必须与文献实际内容匹配：
   - [3]Heckbert（生态经济学ABM综述）被用于支撑"DID反事实/ABM+DID交叉验证"3处 → Heckbert 不讲 DID，应改引 Qi et al.（DID实证）
   - [10]Li et al.（经济政策不确定性对碳价影响）支撑"价格稳定机制（拍卖底价/价格天花板）" → 不匹配
   - [13]Liu et al.（电力企业MADDPG）支撑"为钢铁企业设定高炉-转炉成本函数" → 行业错位
   - [24]Wang et al.（中国低碳转型综述）支撑"某区域两型社会试验区" → 文献不讲该省
   规则：审核清单第10项"引用语境匹配"必须**逐个句子**检查；替换文献后尤其要查（新文献主题可能与原引用位置不符）。修复方式：改引主题匹配的真实文献（Crossref验证）或调整正文表述弱化具体指向
10. **跨文档同步修正（2026.8.7 两次重演教训）**：同一文献的语境错误/旧条目会**跨文档重演**——综述主稿→申报书→综述论文→主题论文共享同一文献库，修正一处后其他文档仍带旧错误：
   - Heckbert 语境错误：综述论文修正删除后，**主题论文初稿 2.2 节又出现** `[Heckbert2010]` 支撑"行为机制嵌入ABM"（同一错误第三次出现）
   - Mizuta 旧条目残留：申报书 [9] 已修正为 2005 Springer 书章节，**主题论文仍引用不存在的 "Mizuta2001" 会议论文**
   规则：发现并修正一处引用问题后，**立即全库扫描同源文档**（`grep` 文献作者名/旧编号于 申报书/综述/论文/主稿），逐一同步；新写作任务引用文献前先对照已修正的权威列表（如申报书 V4.0 51篇），不沿用旧条目
11. **旧值回归陷阱（2026.8.7 v5 终审实测）**：多轮迭代（大修/重写/合并）后，**已经修正过的旧错误值会悄悄回归**——太尉大修 v5 把 [12]杜永善页码从已修正的 120-135 改回旧值 119-135、把 [22] 作者名从已修正的 YAN Z, YUAN Z 改回旧值 ZHOU Y, ZHAO Y（大修时沿用了旧版段落/旧列表）。规则：①大文档多轮修改后，终验必须**对照权威基准版（如申报书 V4.0 列表）逐条核对**关键条目（尤其页码/作者名）②用脚本批量 grep 已知旧错误值（`grep "119-135\|ZHOU Y"`）查回归③修正一处后记录到"已修正清单"，后续每轮终验先查清单上的值是否回归
