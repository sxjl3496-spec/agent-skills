# 基金申报策略师 (Grant Application Strategist)

## 概述

本技能提供从选题到申报书撰写的系统化策略框架，核心目标是**最大化申报成功率**。与论文发表策略（academic-paper-strategist）不同，基金申报的核心逻辑是：**匹配资助机构的战略需求 × 利用申请人已有研究基础 × 选择竞争最小的切入点**。

## 何时使用

- 用户收到基金申报通知/指南，需要决定是否申报
- 用户需要选择申报方向（多个候选方向中选最优）
- 用户需要评估自己的研究基础是否足够支撑申报
- 用户需要撰写申报书（立项依据/研究内容/研究方案/研究基础）
- 用户需要管理申报时间线（截止日期倒排）

## 工作流程

```
阶段一：申报信息收集（指南解读 + 资助偏好分析）
    ↓
阶段二：选题方向分析（2-3个候选 + 成功率评估）
    ↓
阶段三：申报策略制定（研究基础匹配 + 论文展示策略）
    ↓
阶段四：申报书撰写（立项依据 + 研究内容 + 研究方案）
    ↓
阶段四b：Claude Code 独立审查（⭐ 质量门控）
    ↓
阶段五：时间线管理（截止日期倒排计划）
```

### 阶段四b：多Agent并行审查（⭐ 2026.8.1 新增，替代单一Claude Code审查）

申报书初稿完成后，使用 **3个并行agent从不同自然科学视角审查**，比单一Claude Code审查更全面。

**核心原则：审查视角必须与申报学科一致**。用户明确要求："这次是从自然基金，就不要用社科基金的视角了"。

**错误做法**：3个评委分别是运筹学/经济学/交通政策——经济学和交通政策是社科视角，不应用于自科申报书审查。

**正确做法**：3个评委全部是自然科学子学科视角：

| 评委 | 视角 | 审查重点 |
|:---|:---|:---|
| 评委A | 应用数学/运筹学 | MILP建模严谨性、变分不等式应用、优化算法复杂度、数学贡献 |
| 评委B | 系统科学/仿真方法 | ABM行为规则设计、参数校准外部有效性、反事实实验设计、计算可行性 |
| 评委C | 交通工程/计算科学 | 路网建模合理性、信号优化可求解性、数据可获取性、3年计划可行性 |

**执行方式**：用 `delegate_task` 的批量模式（tasks数组），3个agent并行运行。注意v0.16.0的401 bug可能导致delegate_task失败，降级为Claude Code --print分3次审查。

**审查返回后**：
1. 汇总3份评审意见
2. 逐条采纳/驳回（有理由）
3. 修改Word文档
4. 硬验证后提交成品

### 阶段四c：多 Agent 团队写作流水线（⭐ 2026.8.7 实测，碳排放权交易ABM申报书）

当用户以 Team 模式组织申报书写作（角色制：太尉主力写作/御史大夫逐章审核/双辅并行辅助，机制见 aionui-team-leadership 技能"角色制分工"），写作本身遵循以下顺序与策略：

**写作顺序（骨架先行、依据殿后）**：
1. **研究内容最先写**（全书骨架）：凝练"1个核心科学问题 + 3-4项递进研究内容"，递进逻辑用"建模→机制→结构→政策"，前项输出为后项输入（如：行为ABM建模 → 配额分配机制反事实 → 市场微观结构仿真 → 制度情景与交叉验证）
2. **研究方案+技术路线**（依赖内容）：方法复用申请人博士论文工具箱（如损失函数校准/贝叶斯优化/Sobol敏感性/反事实框架），应用领域侧新增该领域特有机制（如碳市场订单簿/配额储存/MSR价格稳定）；技术路线用"内容→平台→情景实验→政策输出"四层结构
3. **立项依据最后写**（最重头，可引用已定稿的研究内容结论）：研究现状用**六段式**——理论演进→方法论比较→国际应用→中国实践→本地五大问题→研究缺口，正面回答"为何本方法而非DID/CGE/DSGE"的排他性论证
4. 研究基础+预期成果+预算+年度计划
5. 整合校对：题目/摘要/关键词/术语统一+参考文献编号统一

**关键策略**：
- **核心科学问题模板**："{政策背景}背景下，{制度要素}如何经由{本省多行业多所有制企业的异质性行为}，涌现为{市场流动性/价格发现/减排效果}的宏观动态？"
- **文献编号保留**：写作期间保留文献综述原编号体系（如[1]-[48]），便于与综述文件交叉核验引文信息，整合阶段再统一改连续编号
- **研究基础最大亮点**：申请人与合作者同源论文（如排污权交易PSM-DID）直接作为"本方法+DID交叉验证"计量模块基础写入，是评审眼中最强的关联证据
- **本地特色贯穿**：本省产业结构反差（如华菱钢铁/有色/工程机械并存）学术化假说、本地五大问题、政策扩围进度情景——不能只贴标签
- **材料供给清单**（开工前向申请人索要）：①申报平台正式模板 ②申请人信息包（简历+已发表/在审论文PDF+代表性论著清单）③本省行业数据 ④博士论文代码路径 ⑤申请代码核实（指南正文只有一级代码如G03，4位代码如G0314以平台填报列表为准）⑥依托单位注册状态
- **时间线预期**：主力 agent 一天可出 V1.0 全稿（38KB 八章），逐章审核流水线比集中审核快且返工少

**⚠️ 团队作战中丞相自身流程纪律（2026.8.7 用户质疑）**：用户发 `/plan` 指令时，即使任务已部分执行/指令清晰，也必须走 plan 技能完整流程（表达优化→输出计划→等确认），不能跳过直接干——用户原话"为什么没有触发/plan这个技能"。中途发现未走流程时：停下→承认→补展示优化+计划（标注已完成）→请确认后继续。

### 阶段四d：临截止论文冲刺策略（⭐ 2026.8.7 用户提议+OpenCode评估）

用户提议：\"在审论文可以充当材料，那么这段时间再产出3篇和主题相关的论文进行在投审稿，岂不是更有说服力？\"（距截止34天）

**可行性评估框架（OpenCode 独立评估，可复用）**：
- 34天3篇：极限压缩11-12天/篇，**有条件可行但风险高**——审稿周期1-3个月，9/10前未必进入"在审"；赶工降质反而不利
- **推荐"2+1"策略**：2篇投稿+1篇备选/后续完善；**质量优先于数量**（2篇高质量 > 3篇低质量）
- **论文类型优先级：综述 > 方法论 > 实证**——综述文献工作量大但技术难度低、审稿快、快速建立领域话语权，是最佳切入点
- **预印本策略**：SSRN/arXiv/哲学社会科学预印本平台可快速发布，作为"在研成果"支撑申报书（不等期刊审稿）
- 期刊选审稿快的 OA 期刊（JCP/Energy Policy 等）；投稿材料（Cover Letter/作者声明）可批量准备
- **风险提示**：申报书"研究基础"重在已发表成果与选题的匹配度，在审论文是加分项非必需品——冲刺应服务申报而非挤占申报主流程时间

**规则**：用户提"用论文冲刺增强申报说服力"时，先让团队（尤其主力写作+审核角色）评估可行性再定，不要盲目接单或盲目反对——用上述框架给出数量/类型/预印本的具体建议。

## 阶段一：申报信息收集

### 需要收集的关键信息

| 信息项 | 来源 | 重要性 |
|:---|:---|:---|
| 项目类别（面上/青年/重点等） | 申报通知 | ⭐⭐⭐ 决定申报门槛 |
| 资助金额和年限 | 申报指南 | ⭐⭐ 影响研究规模设计 |
| 截止时间 | 申报通知 | ⭐⭐⭐ 时间线管理 |
| 申报平台和方式 | 申报通知 | ⭐⭐ 在线填报 vs 下载模板 |
| 依托单位要求 | 申报通知 | ⭐⭐⭐ 需确认本单位是否已注册 |
| 申报条件（年龄/职称/结题限制） | 申报指南 | ⭐⭐⭐ 资格门槛 |
| 优先领域/重点方向 | 申报指南 | ⭐⭐⭐ 选题匹配的关键 |
| 申请书格式要求 | 申报平台 | ⭐ 在线查看 |

### 省级 vs 国家基金的关键差异

| 维度 | 国家自然科学基金(NSFC) | 省级自然科学基金 |
|:---|:---|:---|
| 申报平台 | ISIS系统在线填报 | 各省科技云平台 |
| 模板 | 固定模板可下载 | 通常在线填报，固定格式 |
| 资助金额 | 青年20-30万/3年 | 青年5-10万/3年（各省差异大） |
| 竞争程度 | 极高 | 中等（因省而异） |
| 区域偏好 | 无 | **强偏好本省战略需求** |
| 依托单位 | 需NSFC注册 | 需省科技厅注册 |

### 信息收集实操

1. **登录申报平台**查看完整申报指南（省级通常在省科技厅官网）
2. **确认依托单位**是否已注册（问科研处/院长）
3. **确认优先领域**清单（申报指南中会列出）
4. **下载/查看申请书模板**了解需要填写的栏目

## 阶段二：选题方向分析

### 核心原则：成功率优先

选题不是选"最有创新性的"，而是选**成功概率最高的**。评估公式：

```
成功概率 = 研究基础匹配度 × 湖南省战略契合度 × 方法论创新性 × 竞争优势差异化
```

### 选题评估五维度

对每个候选选题按以下五维度评分（1-5分）：

| 维度 | 评分标准 | 权重 |
|:---|:---|:---:|
| 成功概率 | 综合考虑竞争激烈程度、申报人优势 | 30% |
| 研究基础匹配度 | 已有论文/代码/方法是否能直接复用 | 25% |
| 省份战略契合度 | 是否对接该省"十五五"重点领域 | 20% |
| 创新性 | 选题是否有明显创新点（不能太新也不能太旧） | 15% |
| 可交付性 | 成果形式是否适合"项目毕业制"验收 | 10% |

### 选题分析模板

对每个候选选题输出：

```
选题名称：[具体题目]
研究问题：[一句话]
方法路线：[核心方法]
创新点：[1-2个]
省份契合度：[对接哪个省级战略]
研究基础：[哪些已有论文/代码可复用]
可行性评分：⭐⭐⭐⭐⭐
风险点：[主要风险]
```

### 方法论迁移策略（⭐ 核心）

很多青年教师的博士论文方法论可以直接迁移到新领域：

| 博士论文方法 | 可迁移到的新领域 | 迁移难度 |
|:---|:---|:---:|
| ABM仿真+反事实实验 | 交通拥堵、人群疏散、公共卫生 | 低 |
| 面板计量+DDD | 政策评估、区域经济、劳动经济 | 低 |
| 贝叶斯优化+参数校准 | 机器学习、运筹优化 | 中 |
| 跨期动态优化建模 | 金融决策、消费行为、能源经济 | 低 |

**关键策略**：选择一个你的方法论可以100%迁移的应用领域，而不是去学新方法。申报书"研究基础"部分要突出方法论的可迁移性。

## 阶段三：申报策略制定

### 研究基础展示策略

申报书通常要求列出"已发表论著"和"与本课题相关的研究基础"。

**分层展示法**：
1. **与本课题直接相关的成果**（放在最前面，重点描述方法论关联）
2. **其他已发表成果**（如实列出，展示科研产出能力）
3. **在审/工作论文**（列入"在研成果"，展示持续产出）
4. **代码/数据/平台积累**（列出已有代码库、数据库、仿真平台）

**不要硬扯关联**：如果已发表论文和申报方向无关，如实列出即可，不要强行说"与本项目密切相关"。评审专家看得出来。

### 依托单位策略

- 确认依托单位是否已注册为该基金的"依托单位"
- 如果未注册：通常公告会写"凡有能力承担的法人单位均可申请注册"，在申报平台提交注册申请
- 注册审批通常1-2周，需提前确认
- 区域/偏远地区高校可能有倾斜政策（如湘西高校在湖南省可能有区域配额）

### 论文数量不足的应对策略

| 情况 | 策略 |
|:---|:---|
| 只有1篇SCI/SSCI | 够用（青年基金有1篇高质量论文不算弱） |
| 有CSSCI但与方向无关 | 列入"其他成果"，展示产出能力 |
| 有工作论文/在审论文 | 列入"在研成果"，标注目标期刊级别 |
| 有代码/数据积累 | 在"研究基础"中突出方法论和代码资产 |
| 合作论文（非一作） | 如实列出，标注作者顺序 |

**核心原则**：不需要"充数量"。青年基金评审看重的是**研究基础与申报方向的匹配度**，不是论文总数。5篇已发表+4篇在审在35岁以下青年教师中属于中上水平。

## 阶段三b：合作者策略（⭐ 2026.8.1 新增）

### 是否需要合作者

| 问题 | 回答 |
|:---|:---|
| 没有合作者会被拒吗？ | 不是直接被拒，但是扣分项 |
| 青年A类对团队配置的要求 | 低，主要看个人，但1-2个成员几乎零成本 |
| 评审重点 | 选题+可行性+研究基础，不是团队规模 |

**结论**：不一定要找合作者，但挂1-2个校内成员几乎零成本，建议做。

**⚠️ 例外（2026.8.7 实测）：联合基金跨单位参与者成本高，能个人就个人**。省教育厅联合基金若挂**外校**参与者（如硕导在湘潭大学），该单位即"参与单位"，需**签订合作协议并上传**（联合基金明确要求；无参与单位则填"无参与单位"+信用代码18个0+声明附件）。青年B类为个人申报、不需参与者，跨单位合作的手续（协议签署/盖章/上传）耗时且不必要——用户决策：**能个人就个人**，合作者的支撑通过研究基础（共同论文）呈现即可，评审价值不受影响。校内成员才适用"零成本挂名"。

### 合作者评估流程

1. **搜索学术成果**：用 Google Scholar（走 Clash 代理端口7897）搜索合作者的英文和中文论文
2. **提取关键信息**：论文数、最高引用、总引用、期刊分布、研究方向
3. **评估与申报方向的关联度**：找出合作者真正的专长，而非你想让他做的事情
4. **确定角色定位**：合作者的角色必须与其实际研究方向一致

### 合作者角色定位原则（⭐ 关键）

**错误做法**：让运筹学方向的老师"补运筹学背景"，但他实际不做运筹学
**正确做法**：根据合作者的实际研究方向定位其角色

| 合作者实际方向 | 申报书中的角色定位 |
|:---|:---|
| 统计学/试验设计 | "负责仿真实验的统计设计与参数校准" |
| 运筹学/最优化 | "负责信号控制优化的数学建模" |
| 图论/网络科学 | "负责路网拓扑建模与关键节点分析" |
| 经济学/计量 | "负责福利效应测度与政策评估" |

### 找院长挂名的策略

找院长比找普通老师好：
- 院长挂名=学院支持，分量重
- 以后要数据/经费/场地都方便
- 他给你发了基金通知，你请他挂名是顺水推舟

**开口话术模板**：
> "X院长，我看了您发的[年份]省自科青年基金通知，准备申报一个[方向]的课题，用[核心方法]做[研究对象]。我第一次报省自科，想请您作为项目组成员支持一下。课题里涉及[合作者的实际专长]，正好是您的研究方向。"

### 同时申报省自科和省社科的策略（⭐ 2026.8.1 新增）

用户可能想用同一个研究方向同时申请省自科和省社科，以最大化获批概率。

**规则：同年同一课题不能同时申请省自科和省社科（避免重复资助），但不同课题可以分别申请。**

**拆分方案**：将一个大方向拆为两个互补课题：

| | 省自科（方法导向） | 省社科（应用导向） |
|:---|:---|:---|
| 课题核心 | 怎么建模/怎么优化/怎么仿真 | 谁受益/谁受损/改善多少 |
| 学科归属 | 应用数学/系统科学 | 经济学/管理科学 |
| 方法论 | ABM仿真 + MILP优化 + 变分不等式 | 计量经济学 + 福利分析 + 政策评估 |
| 关系 | 产出"工具"（仿真平台+优化模型） | 用工具做"经济分析" |

**时间不冲突**：省自科通常8-9月截止，省社科通常10-12月或次年1-3月截止。先冲省自科，再用省自科的ABM仿真平台成果作为省社科的数据基础。

**建议**：不建议同一年同时冲两个。先省自科（准备充分），省社科等通知出来再启动。省社科选题可以复用省自科的方法论积累，但研究内容必须不同。

### 鼓励用户提出跨域类比（⭐ 创新来源）

用户的创意往往是最好的创新来源。本案例中，用户提出"碳排放权交易→交通出行权交易"的类比，直接催生了申报书的核心创新概念。

**策略**：在选题讨论中主动引导用户思考：
- "你博士论文的方法论能迁移到哪个应用领域？"
- "你学过的哪些理论框架可以类比到新场景？"
- "你做过的哪篇论文的方法可以直接用在新课题里？"

### 多合作者互补策略（⭐ 2026.8.1 新增）

当一个合作者无法覆盖所有短板时，使用两个互补的合作者：

| 合作者类型 | 补的短板 | 角色定位示例 |
|:---|:---|:---|
| 本校院长/系主任 | 行政支持+本领域专长 | "统计设计/参数校准/学院资源协调" |
| 博士导师（外校） | 学术血缘+方法论背书 | "运筹学理论/最优化建模/方法指导" |

**效果**：两个合作者一挂，评审专家看到的是完整团队配置（如"数学+统计+运筹学"），学科跨越风险基本化解。

**可行性**：省自科青年A类没有要求项目组成员全部来自依托单位，外校导师完全可以作为成员。

详见 `references/collaborator-evaluation-mengkaiwen-case.md`。

## 阶段四：申报书撰写

### 申报书标准结构

> **重要**：国自然和省自科的模板结构不同。国自然有固定模板可下载（GitHub上有LaTeX版：iNSFC，514 stars），省自科通常在科技云平台在线填报。

#### 国自然2026版结构（五段式，正文≤30页）

从 GitHub iNSFC 模板（`YimianDai/iNSFC`）的 `青A.tex` 中提取的官方结构：

```
报告正文（2026版）

（一）主要学术成绩、创新点及其科学意义（建议不超过5000字）
    着重阐述近5年来在基础研究方面所取得的学术成绩、创新点、研究价值和科学意义等。

（二）拟开展的研究工作（建议不超过3000字）
    着重阐述拟开展的研究工作的创新性构思，主要研究方向和初步研究方案等。

（三）其他需要说明的情况
    1. 同年申请不同类型项目情况
    2. 高级职称人员单位不一致情况
    3. 正在承担的相关项目情况
    4. 完成基金项目情况
    5. 其他
```

> 注意：2026版国自然青A只有两段正文+一段说明，**不是**传统的"立项依据+研究内容+研究方案+研究基础"四段式。但2025版C类模板显示有更详细的五段结构（立项依据/研究内容/研究基础/其他），可能是A类和C类模板不同。需以实际下载的模板为准。

#### 省自科结构（通常在线填报）

省自科通常在科技云平台在线填报，格式固定，大致包含：

| 部分 | 内容 | 字数建议 | 撰写策略 |
|:---|:---|:---:|:---|
| 项目基本信息 | 名称/类别/金额/年限 | 固定 | 名称要体现方法和应用场景 |
| 立项依据 | 研究意义+国内外现状 | 3000-4000字 | ①对接省级战略 ②指出研究缺口 ③提出解决方案 |
| 研究内容 | 3-4个递进式研究内容 | 2000-3000字 | 从机制分析->方法构建->策略评估递进 |
| 研究方案 | 方法+技术路线+可行性 | 2000字 | 突出方法论积累和技术路线图 |
| 研究基础 | 已有成果+前期积累 | 1000字 | 分层展示法（见阶段三） |
| 工作条件 | 依托单位条件+资源 | 500字 | 计算资源+数据可获取性 |
| 经费预算 | 按资助金额编制 | 表格 | 合理分配（材料/测试/会议/差旅） |

> ⚠️ 省自科的具体格式必须登录科技云平台确认，各省不同。以上为常见结构参考。

### 立项依据撰写要点

1. **第一段就提省级战略**：对接该省"十五五"规划中的重点领域
2. **实际问题入手**：从一个具体的现实问题切入（如交通拥堵、环境污染）
3. **指出研究缺口**：现有研究缺了什么？为什么这个缺口重要？
4. **提出解决方案**：本文用什么方法填补这个缺口？
5. **创新点明确**：2-3个具体创新点，每个一句话说清楚

### 技术路线图

用文字描述技术路线（在线填报通常不支持图片），结构化为：

```
研究内容1（机制分析）
    ↓ 输出：理论模型/规律发现
研究内容2（方法构建）
    ↓ 输出：仿真平台/优化算法
研究内容3（策略评估）
    ↓ 输出：政策建议/反事实实验结果
```

## 常见陷阱

### 陷阱1：选题太"新"导致研究基础不足

**问题**：为了追求创新性选择一个全新方向，但已有论文和代码都不能复用，评审专家质疑"研究基础不足"。

**解决**：选择方法论可以100%迁移的应用领域。创新点在"方法迁移到新领域"，而不是"从零开始做新方法"。

### 陷阱2：忽略省级基金的区域偏好

**问题**：用国自然的选题逻辑套省级基金，忽视了省级基金对本省战略需求的强偏好。

**解决**：立项依据第一段就提本省战略。选题最好能对接本省具体的应用场景（如长株潭都市圈、张家界旅游、洞庭湖生态等）。

### 陷阱3：申报书过长或过短

**问题**：在线填报有字数限制，过长被截断，过短显得不充实。

**解决**：每个部分控制在建议字数范围内。重点放在立项依据和研究内容上。

### 陷阱4：未确认依托单位注册状态

**问题**：到了截止前一周才发现依托单位没注册，无法提交。

**解决**：收到申报通知后第一时间确认依托单位是否已注册。未注册的需提前1-2周提交注册申请。

### 陷阱5：cross_model_verify 验证长申报书时截断

**问题**：申报书超过4000字符时，cross_model_verify 的 content 参数被API截断，验证器只看到前半部分，可能误报后半部分"缺失"。

**解决**：不要信任 cross_model_verify 对长文档的"内容缺失"报告。用 `grep`/`search_files` 做硬验证确认关键章节实际存在。

### 陷阱6：Web搜索在基金调研中全面失效（⭐ 2026.8.1 实测）

**问题**：调研湖南省自科基金申报信息时，百度/Google/Bing三种搜索引擎的HTML解析全部失效（返回空结果），知乎/小木虫等平台也因JS渲染无法提取内容。

**根因**：
- 百度搜索：`session.trust_env = False` 绕过代理后可访问，但搜索结果HTML是JS动态渲染，`re.findall` 提取不到内容
- Google搜索：通过 Clash 代理（端口7897）可访问，但同样JS渲染
- Bing搜索：同样JS渲染
- 政府网站：湖南省科技厅 `http://kjt.hunan.gov.cn` 可访问但返回内容极少

**可靠替代方案**：
1. **GitHub API**（✅ 最可靠）：`curl -s "https://api.github.com/search/repositories?q=KEYWORD&sort=stars"` 返回结构化JSON，可直接 `json.load` 解析
2. **PyMuPDF + vision_analyze**（✅ 对扫描版PDF有效）：见陷阱7
3. **用户自行登录平台**：申报指南详细内容需用户自行登录科技云平台查看，AI 无法替代

**规则**：基金调研中不要依赖Web搜索引擎。GitHub API 用于找开源工具和参考文献，政府信息让用户自行查看。

### 陷阱7：扫描版PDF无法直接提取文字（⭐ 2026.8.1 实测）

**问题**：用户的简历/论文PDF是扫描版（图片格式），PyPDF2 和 pdfplumber 都返回空字符串，`vision_analyze` 直接传PDF路径也不识别（"source is not a recognized image"）。

**解决**：用 PyMuPDF (fitz) 将PDF每页渲染为PNG，再用 `vision_analyze` 逐页识别：

```python
import fitz  # PyMuPDF
doc = fitz.open(pdf_path)
for i, page in enumerate(doc):
    pix = page.get_pixmap(dpi=200)  # 200dpi 足够OCR
    pix.save(f"page_{i+1}.png")
# 然后对每张PNG调用 vision_analyze
```

**注意**：
- `dpi=200` 足够OCR识别，更高会增加传输时间
- `vision_analyze` 对大图可能超时（>2MB），需控制图片大小
- 3页简历PDF用此方法成功提取了全部5篇论文信息（含作者顺序、期刊名称、级别）

### 陷阱8：Google Scholar 搜索返回CSS而非结果（⭐ 2026.8.1 实测）

**问题**：通过 Clash 代理（端口7897）访问 Google Scholar 搜索某作者论文时，返回的是CSS样式表而非搜索结果HTML。

**根因**：Google Scholar 的反爬机制，对非浏览器 User-Agent 或异常请求模式返回重定向页面。

**解决**：设置完整的浏览器请求头：

```python
session.headers.update({
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36',
    'Accept': 'text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8',
    'Accept-Language': 'en-US,en;q=0.9,zh-CN;q=0.8,zh;q=0.7',
})
proxies = {'http': 'http://127.0.0.1:<代理端口>', 'https': 'http://127.0.0.1:<代理端口>'}
```

**提取论文数据**：用正则提取标题（`<h3 class="gs_rt">`）、作者行（`<div class="gs_a">`）、引用数（`Cited by (\d+)`），可获取作者的完整论文清单、引用数和期刊分布。

**注意**：中文作者搜索时，同时用英文名和拼音搜索（"合作者A" 和 "学院院长"），两者结果互补。

### 陷阱9：合作者角色定位错误（⭐ 2026.8.1 实测）

**问题**：评估合作者时，主 agent 先入为主地认为院长"补运筹学方向"，但实际搜索后发现院长的方向是统计学/试验设计（均匀设计、偏差下界），不是运筹学（线性规划/整数规划）。

**根因**：用户提到"运筹学"一词，主 agent 直接将合作者定位为运筹学方向，没有先搜索确认其实际研究方向。

**解决**：**先搜索合作者的实际研究方向，再确定角色定位**。Google Scholar 搜索合作者英文名+单位，提取其论文清单和研究方向，然后根据实际方向确定申报书中的角色描述。

**规则**：合作者的角色描述必须与其已发表论文方向一致。不能让统计学教授"补运筹学背景"，但可以让他"负责仿真实验的统计设计与参数校准"——试验设计就是统计学教授的本行。

### 陷阱10：Google Scholar 频繁反爬限制，arXiv API 降级方案（⭐ 2026.8.1 实测）

**问题**：Google Scholar 搜索某作者时，即使设置了完整浏览器请求头，仍频繁返回CSS重定向页面而非搜索结果（特别是连续搜索2-3次后）。

**降级方案**：用 arXiv API 搜索作者的预印本，作为 Scholar 的补充/替代：

```python
import requests
resp = requests.get(
    'http://export.arxiv.org/api/query?search_query=au:"作者英文名"&max_results=15',
    proxies={'http': 'http://127.0.0.1:<代理端口>', 'https': 'http://127.0.0.1:<代理端口>'},
    timeout=20
)
# 解析返回的 Atom XML feed
entries = re.findall(r'<entry>(.*?)</entry>', resp.text, re.DOTALL)
```

**搜索策略（多关键词交叉）**：
1. Google Scholar 搜索 `"K Meng" "X Yang"`（作者名+常见共同作者）→ 获取期刊论文
2. arXiv API 搜索 `au:"合作者B"` → 获取预印本
3. 两者合并去重，构建完整论文清单

**优势**：arXiv API 返回结构化 XML，不依赖JS渲染，不受反爬限制。
**局限**：只能找到发在 arXiv 上的预印本，纯期刊论文（未传arXiv）需通过 Scholar 补充。

### 陷阱11：课题学科归属定位错误——省自科不收社会科学课题（⭐⭐ 2026.8.1 实测）

**问题**：申报书内容偏经济学（福利效应、分配公平、行为助推），评审专家可能判定"这是社科课题，不该来自科"，直接拒掉。

**根因**：
- **国自然有管理科学部（G学部）**，经济学/管理学可以正常申请
- **省自科各省政策不同**：有些省的省自科不资助管理科学/经济学方向，只有数理/工程/信息等自然科学学科代码
- 申报人若以经济学视角写申报书，可能找不到对应的学科代码

**判断标准**：同一个研究可以归到不同学科。关键是怎么"包装"：

| 侧重什么 | 归属学科 | 能否申请省自科 |
|:---|:---|:---|
| 福利效应、分配公平 | 经济学（社会科学） | ⚠️ 有风险 |
| ABM仿真方法、信号优化算法 | 应用数学/信息科学 | ✅ 安全 |
| 交通拥堵建模、网络优化 | 系统科学/运筹学 | ✅ 安全 |
| 机制设计+市场均衡+仿真 | 交叉学科 | ✅ 公告说"促进跨学科交叉" |

**解决策略：以"方法"为核心，经济学为应用背景**

核心原则：**用数学方法解决实际问题，经济学理论是工具不是主体**。具体做法：

| 申报书中的表述 | 偏社科（❌ 避免） | 偏自科（✅ 采用） |
|:---|:---|:---|
| 课题类型 | 出行权交易的福利效应研究 | 出行权交易机制的数学建模与仿真 |
| 研究内容 | 分配公平分析 | 治理策略的仿真评估与绩效比较 |
| 关键词 | 福利经济学、行为助推 | 多智能体仿真、混合整数规划、网络优化 |
| 学科归属 | 经济学 | 应用数学/交叉学科 |
| 申请代码 | G（管理科学，如省里有） | A（数理科学）或 G（如省里有） |

**语言转换技巧**：经济学概念可以用数学语言重新表述而不改变内容：
- "福利效应"→"绩效评估"
- "分配公平"→"效果比较"
- "帕累托改进"→"优化目标函数"
- "行为助推"→"选择架构优化"
- "市场均衡"→"变分不等式求解"

### 陷阱12：将应用领域概念误认为学科方向（⭐ 2026.8.1 实测）

**问题**：用户提出"绿波路段作为助推（nudge）效应"，这个概念本身很好，但"助推"是行为经济学的术语，在省自科申报书里使用会让评审专家觉得"这不是自然科学"。

**解决**：创新概念可以用，但要用数学/工程语言重新包装：
- "绿波助推效应"→"绿波信号控制的协同优化与车流诱导机制"
- "行为助推"→"选择架构对决策路径的引导作用"
- 概念不变，但表述从社会科学语言转为自然科学语言

### 陷阱13：多Agent审查视角与申报学科不一致（⭐ 2026.8.1 用户纠正）

**问题**：计划用3个agent审查申报书，评委视角分别是"运筹学/经济学/交通政策"。用户纠正："这次是从自然基金，就不要用社科基金的视角了"。

**根因**：经济学和交通政策属于社会科学视角，不应用于自然科学基金申报书的审查。社科视角的评委可能会建议加入福利分析、分配公平等社科元素，反而将申报书推向不安全区域。

**规则**：审查视角必须与申报学科完全一致。省自科申报书=全部自然科学视角，省社科申报书=全部社会科学视角。跨学科申报书可以混合，但必须有明确的主学科归属。

**记忆要点**：此纠正已嵌入阶段四b的多Agent审查流程中。

### 陷阱17：跨领域申报是成功率第一杀手（⭐⭐ 2026.8.2 用户纠正+实测）

**问题**：申请人有9篇经济学方向论文（PLOS ONE SCI+JASSS SSCI在审+保险研究CSSCI×2+产业经济评论CSSCI+湘潭大学学报CSSCI），却选择申报交通与运载工程（E12）方向，因为交通方向"更有创新性"和"对接湖南需求"。

**结果**：评审专家第一眼看"有没有交通领域论文产出"——0篇。在博士贬值元年（2025）+再贬30%（2026）的竞争环境下，评审专家不缺有交通背景的申请人，没有理由选一个做彩票的人来做交通。

**用户原话**：
> "我的目的是要用最大概率拿到一个省级课题项目。要用最客观的态度，来帮助我成功拿到一个基金。"

**核心原则**：**成功率 = 研究基础匹配度 × 其他因子。研究基础匹配度是乘数，不是加数。0篇领域论文 = 乘数为0 = 成功率趋近于0。**

**决策框架**：

| 问自己 | 如果回答是 | 那么 |
|:---|:---:|:---|
| 我在这个方向有几篇论文？ | 0篇 | **放弃这个方向** |
| 我的方法论能迁移吗？ | 能 | 方法学迁移≠研究基础匹配。评委看的是"产出"不是"能力" |
| 新方向对接政策需求吗？ | 是 | 政策对接是加分项（加数），不能弥补0篇论文（乘数=0） |
| 旧方向有论文但不够新？ | 是 | "不够新但有论文"比"很新但没论文"成功率高3-4倍 |

**正确策略**：
1. **先列全部已发表论文，找对口学科代码**
2. **选论文数最多的方向，而不是最有创新性的方向**
3. **创新点放在"方法论迁移到新应用场景"，而不是"从零开始做新领域"**
4. **新方向可以入职后做第二个课题，用第一个项目的经历提升第二次成功率**

**真实案例对比**：

| | 交通方向（E12） | 经济科学方向（G03） |
|:---|:---|:---|
| 领域论文数 | 0篇 | 9篇全部对口 |
| 跨领域风险 | 高（从彩票跨到交通） | 零（直接延续博士论文） |
| 研究基础评分 | 2/5 | 4/5 |
| 成功率 | 15-20% | 30-40% |

### 陷阱28：合作者不熟悉申报方向时不能强拉（⭐ 2026.8.2 用户反馈）

**问题**：为了让院长（学院院长，均匀设计方向）参与碳排放权交易课题，设计了一个"均匀设计+ABM仿真"的选题让他感兴趣。但用户反馈："我对欧院长的研究领域一点都不擅长，他能带着我申请课题吗？"

- 欧院长做纯理论统计（均匀设计、偏差下界），用户完全不懂这个方向

### 陷阱31：准备客观评审材料时不能夹带主观判断（⭐⭐ 2026.8.2 用户两次纠正）

**问题**：将候选课题方向交给3个外部AI工具独立评审时，在材料中标注了"方向E（已否决）"，用户纠正："说了不能带主观，你怎么直接否决掉了"。随后又遗漏了方向F（ABM+AI算法课题），用户再次纠正："还有我之前提到的几个课题和研究方向，也要列出来"。

**根因**：agent将自己的分析结论（"交通方向成功率低，应放弃"）混入了本应纯客观的评审材料中，污染了外部评审者的独立判断。第二次遗漏是因为agent没注意到用户之前提到的"AI算法相关课题"方向。

**规则**：当用户要求准备"客观材料"给外部评审者时：
1. **所有候选方向平等列出，不标注"已否决"/"不推荐"/"成功率低"等任何主观标签**
2. **即使之前已和用户讨论过并似乎达成了共识，材料中也不能预设结论**
3. **逐条核对用户提及的所有方向是否全部包含**，遗漏一个就会被用户抓住
4. **用户提供的新方向（如"还有AI算法相关的课题"）必须立即纳入，不能遗漏**
5. **如果agent认为有遗漏的方向，可以单独提示用户，但不能在评审材料中预设**

### 陷阱36：cross_model_verify 不能当"评审员"用（⭐⭐ 2026.8.2 实测）

**问题**：6模型并行评审中，用 `cross_model_verify` 脚本调DashScope API（qwen3.7-max和qwen3.7-flash）做评审，两个API都把评审材料当作"交付物"来检查质量，输出"材料完整性审查报告"而非"评审意见"。

**正确做法**：需要模型"基于材料做评审/分析/判断"时，用 `execute_code + requests` 直接调API，不用cross_model_verify。详见 `references/local-ai-tools-independent-review.md` 第四节。

**判别规则**：
- prompt="检查以下内容是否覆盖XX维度" → cross_model_verify（验证模式）
- prompt="基于以下材料回答/评估/分析" → 直接API调用（评审模式）

### 陷阱39b：Crossref API是学术文献搜索的最可靠工具（⭐ 2026.8.2 实测）

**问题**：调研碳排放权交易领域文献时，Semantic Scholar API频繁429限流，百度/Google搜索结果为JS渲染页面无法解析。

**解决**：用Crossref API搜索学术论文，返回结构化JSON（标题、作者、期刊、DOI、年份），不受反爬限制：

```python
import requests
session = requests.Session()
session.trust_env = False

resp = session.get(
    "https://api.crossref.org/works",
    params={
        "query.bibliographic": "agent-based model carbon emissions trading simulation",
        "filter": "from-pub-date:2020-01-01,type:journal-article",
        "rows": 20,
        "sort": "score",
        "order": "desc"
    },
    timeout=30
)
items = resp.json()["message"]["items"]
for item in items:
    title = item.get("title", [""])[0]
    # 过滤相关论文
    if any(kw in title.lower() for kw in ["carbon", "emission", "trading", "agent-based"]):
        print(f"  [{year}] {title} - {journal}")
```

**优势**：无需认证、无反爬限制、返回结构化数据、可按关键词+日期+类型过滤。

**局限**：只有Crossref收录的论文（大部分SCI/SSCI期刊都在），中文期刊覆盖不全。

**多关键词搜索策略**：用`query.bibliographic`参数做精确搜索，比`query`参数更精准。单次搜索可返回20条，多次搜索不同关键词组合可覆盖更多文献。

### 陷阱42：参考文献必须逐条真实核验，简化条目是重大学术隐患（⭐⭐ 2026.8.7 用户督办）

**问题**：申报书初稿参考文献用"作者+标题+期刊+年份"简化格式。用户批评："引用都有残缺，这个是重大学术问题，参考文献必须真实，引用格式必须是GB国标格式，不能有信息残缺！" 用 Crossref 逐条核验 52 篇后发现：**7篇疑似编造**（Crossref 查无此文，如"Liu Z, Wang C. China carbon market. Applied Energy, 2022"完全无匹配）、**3篇信息错误**（卷号/页码/作者不符，如 [34] 页码 159-175 实为 404-417）、若干篇缺卷期页码。评审若核查=学术诚信事故。

**分工铁律（用户 2026.8.7 原话）**："文献这一块的活，你不能交出去给其它agent，你有全面的技能，其它agent没有，你的学术技能最完善。文献这一块的活，你不能分配出去，你得自己把握住"——申报书/论文的**参考文献核实必须由具备学术技能的主导 agent（如 Hermes）亲自执行**（Crossref+PDF 双重验证），**不外包给辅助队友**。实测教训：辅助队友 Aion CLI "补全"的卷期页码大量编造（18 篇中文文献 16 篇页码错误）。辅助队友可整理初稿/查缺，但最终逐条核实必须主导者亲手做。技术方法见 `references/literature-verification-workflow.md`。

**核验方法**（Crossref API，逐条查询）：
```python
import requests
session = requests.Session(); session.trust_env = False
resp = session.get("https://api.crossref.org/works", params={
    "query.bibliographic": "论文标题关键词",
    "query.author": "第一作者姓",
    "rows": 3,
    "select": "DOI,title,author,container-title,volume,issue,page,published",
}, timeout=25)
# 比对：标题/作者/刊名/年/卷/期/页/DOI 是否与申报条目一致
```
- 匹配到真实文献但信息不符 → **修正**（以 Crossref 为准）
- 查无此文 → **删除或替换**为真实文献（保持引用编号连续，正文引用同步迁移）
- 经典文献（Coase 1960 等太老，Crossref 收录不全）→ 用公认标准信息（JLE, 1960, 3: 1-44；Econometrica, 1979, 47(2): 263-291）
- 中文文献 → 与本地 PDF/文献矩阵库核对补全卷期页码

**规则**：
1. **所有参考文献必须经 Crossref/DOI 可查证**，禁止"看起来合理"的占位条目
2. GB/T 7714 完整性（作者全名/标题/刊名/年/卷/期/页码齐全）是**审核必查项**——审核清单必须含"卷期页码逐条核对"（御史大夫曾漏检此项被用户批评）
3. 删除/替换后引用编号必须重新连续化，正文引用同步迁移

### 陷阱43：主导者必须独立终审，不能只转述评审意见（⭐⭐ 2026.8.7 用户纠正）

**问题**：申报书终审时，lead（丞相）直接转述御史大夫的评分结论（86.8分通过），用户批评："你最后验收也要对终稿进行审核，给出评价呀，你只能参考御史大夫的评价，你自己要做最终审核呀"。

**规则**：多Agent评审流程中，主导者收到评审意见后必须：

### 陷阱44：在审论文对青年B类的加分权重有限（2026.8.7 御史大夫评审视角）

### 陷阱24：同一论文基础下细分选题的选择（⭐ 2026.8.2 实测）
