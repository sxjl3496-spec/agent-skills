# 省自科申报书多Agent写作流水线（2026.8.7 实战案例）

> 来源：湖南省教育厅联合基金青年B类（20万/3年）碳排放权交易ABM方向申报书 V1.0→V2.0 实战。
> 角色体系（少帅钦定）：太尉（Claude Code）=主力写作；御史大夫（OpenClaw）=逐章审核；双辅（Aion CLI/OpenCode）=文献/数据/格式辅助；丞相（Hermes）=统筹+质量门控。

## 一、写作顺序：骨架先行、依据殿后（依赖驱动）

| 顺序 | 章节 | 要点 |
|---|---|---|
| 1 | 研究内容（骨架，最先写） | 1个核心科学问题+4项递进内容（建模→机制→结构→政策，前项输出为后项输入） |
| 2 | 研究方案+技术路线 | 复用申请人已有方法论工具箱（如博士论文 ABM+校准+反事实），应用侧新增机制要素 |
| 3 | 立项依据（最重头，殿后写） | 背景意义→六段式现状（理论演进→方法比较→国际应用→中国实践→省域问题→缺口）→创新点；正面回答"为何本方法而非替代方法"的排他性论证 |
| 4 | 研究基础+预期成果+预算+年度计划 | 分层展示（直接相关成果置顶+其他成果+在研+代码资产） |
| 5 | 整合校对 | 题目/摘要/关键词/术语统一+参考文献连续编号 |

**为什么研究内容先写**：它定全书骨架，立项依据需引用已定稿的研究内容结论；34天截止期下避免写完依据发现内容改了要重写。

## 二、逐章流水线审核（避免截止前集中返工）

太尉每交付一章→御史大夫即审→返工→下一章。审核产出三层结构：
1. **逐章问题清单**：表格（序号/章节/问题类型/描述/严重程度🔴🟡🟢/修改建议+行号定位）
2. **全书评分卡**：创新性/可行性/写作质量/格式规范，百分制
3. **终稿审核意见**：总评+必须修改硬伤+建议修改+亮点+修改优先级（V2.0必须/建议/答辩补充）

审核视角必须与申报学科一致（自科申报书=自然科学视角，勿用社科视角）。

## 三、碳ABM方向申报书评审雷区（御史大夫48项问题提炼的通用模式）

### 🔴 硬伤级（V2.0 必须修）
1. **参考文献编号断裂**：正文声称引用48篇但文末只列24篇、编号跳跃（缺7-9/12/17等）——评审会逐一核对，是最大格式硬伤。**教训**：正文引用编号必须与文末列表连续对应；写作时引用综述的编号体系（[1]-[48]）时，整合阶段必须统一重排
2. **Q-learning 收敛性未论证**：碳市场交易频率远低金融市场（约750个履约交易日/3年），智能体学习样本是否足够？**修法**：收敛诊断指标+不收敛备选方案（如规则式适应性学习）
3. **ABM+DID 交叉验证逻辑循环**："用ABM生成数据检验DID偏误"实质预设结论（ABM若含DID捕捉不到的异质性，DID当然失效）。**修法**：①用ABM复现已有DID实证结论（方向+量级）检验外部效度；②ABM生成反事实场景揭示DID偏误方向和条件

### 🟡 重点级（评审常见扣分点）
4. **数据可得性与经费预算矛盾**：前文强调数据"公开可得"、预算却列"数据采集费3.0万"——必须统一口径（改"数据整理处理费"或明确哪些数据需购买+给出3-5个具体数据源）
5. **误引文献**：把 LLM 生成式智能体论文（如 Park et al. 2023 "Generative Agents"）当作传统 ABM 引用——评审专家会注意到范式区别
6. **"首次应用/首次迁移至XX"类创新力度弱**：评审认为是增量工作。**修法**：强化方法论层面创新（迁移过程中针对目标场景做了哪些方法改进/参数化调整）
7. **方法细节缺失**：CGE 软耦合不写清模型选择（GTAP/自建SAM/部门划分）、金融工具行为规则不写（谁发行/参与条件/违约处理）→ 补技术细节
8. **智能体规模过度工程化**：碳市场重点排放单位仅200-500家，写"10000+智能体"会被质疑——论证规模选择依据
9. **行为参数缺依据**：前景理论参数（λ/α/β）、分布假设（对数正态 μ/σ）需给出来源或纳入校准框架
10. **Q-learning 等复杂行为规则的收敛条件**、反事实实验的统计功效（30次重复×6组能否检测显著差异）、四维情景组合规模（用正交/LHS降维）——可行性部分要预答

## 四、多Agent执行要点（本次踩坑）

- **队友发消息 JSON 转义**：stdin JSON 里 Windows 反斜杠路径报 `invalid escape` → 用 Python `json.dumps(ensure_ascii=False)` 生成再管道（详见 openclaw-ops 陷阱14）
- **无 exec 队友的文件回传机制**：在队友 workspace 建固定报告目录，汇报写成 `<YYYYMMDD>_<主题>.md`，Leader 轮询；需队友审核的文件复制进其 workspace，路径用相对形式（详见 openclaw-ops 陷阱12/13）
- **任务板分工**：每个章节一个任务，写/审分开（太尉的写任务+御史大夫的审核任务），状态随交付流转（completed/in_progress）
- **双辅并行**：参考文献整理（GB/T 7714 连续编号）+ 申报要求对照清单 + 省域数据检索，与主笔并行，不占主笔时间

## 五、时间线（34天倒排实测）

8/7-8/15 研究内容+方案初稿 → 8/16-8/22 立项依据 → 8/23-8/30 审核+修改 → 9/1-9/9 定稿提交。
实际执行：太尉一次成型 V1.0（8章全）提前约10天；御史大夫全稿审核（48项问题+评分卡74.5/100）当日完成。**V1.0 不必逐章交付，可全稿后一次审核**（前提是审核产出按章组织）。

## 六、V2.0→V2.1 收尾实战（评分 84.3→86.8，终审通过）⭐⭐

**审核→返工→复审→终审全流程实测**：V1 初审（48项，74.5）→ V2.0 返工（复审 84.3）→ V2.1 表单化+少帅指示（终审 **86.8，准予提交**）。单日完成，审核闭环靠的是返工令按优先级分级（🔴必须/🟡重点/🟢低成本），返工报告逐项对照原问题编号（#31/#44/#8...），复审时逐项验证修复真实性。

### 收尾阶段常见事项（本次6项+3项🟢）
1. **文献作者名逐篇联网核实**：初审发现[19]作者名乱码（RENGS B）、[29]-[33]缺作者名——返工时不只补名，还要**核实卷号/标题真实性**（本次多篇卷号错误被修正，如[29] Applied Energy 2024, 372 实为 385；[30] 正文"Tang等八大行业"实为"Liu等电力企业MADDPG模型"——正文描述也要跟着改）。GB/T 7714 硬性要求作者全名
2. **字数控制**：V2.0 扩到 61KB md（约2万字）→ 核实平台限制（正文≤12000字）→ 精简到 **11215字**（含参考文献12446字另计），61KB→27KB。61KB md ≈ 2万字，超限必精简
3. **在审论文写不写？** 少帅疑问"在审的论文写上去有意义吗"——**有**：列入"在研成果"展示持续产出能力，规范标注"在审"（如 JASSS 在审=ABM 权威期刊，是加分项）
4. **代码/数据资产可验证化**：研究基础写代码复用（校准框架100%/主体80%等模块级比例），附 GitHub 开源链接（从博士论文终稿末页提取，如 p166）——评审可验证，比空口说"有代码积累"可信
5. **纯个人申报的表述调整**：合作者不挂参与者后，正文改"前期合作研究"表述，共同论文保留在研究基础（删除一切"参与者/成员/挂名"字样）
6. **表单字段就绪清单**：〇章节放"平台填报字段速览"（步骤2字段+约束校验+完成标记），填报时逐字段对照，避免漏填

### 🟢 终审后遗留小项（不影响提交）
- 待确认清单删除已完成项（防止"已修复"与"待确认"矛盾表述并存）
- 部分文献页码缺失：GB/T 7714 建议补全，非必须

### Word 版生成
少帅要"最终版 Word"时：`pandoc 申报书.md -o 申报书.docx --toc --toc-depth=2`（本机 pandoc 3.8.3 已验证，中文+表格转换正常）。**只在定稿后生成**，中间稿不生成（少帅明确只要最终版，避免多版本混淆）。
