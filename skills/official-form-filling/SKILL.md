# 官方表格/公文填写 (official-form-filling)

用户是高校教师，经常需要填写上报省人社厅/教育厅的官方表格（专业一致性说明、政审表、报名表、考核表、证明）。此类模板常为 docx（或旧 .doc、扫描版 PDF），含 `XXX`、`XX大学`、`XXXXXXXXXX` 等占位符。本技能沉淀完整套路（2026.8.5 专业一致性说明实战验证）。

## 铁律：只填占位符，绝不改模板措辞 ⭐

**用户明确纠正（2026.8.5）**："你不要修改模板，那是人家给过来的模板，你把那个信息填进去可以了，不要修改它的模板"。模板是上级单位发的固定格式，**只能把 XXX/XX 占位符替换成真实值，模板本身的措辞、句式、结构一字不动**。

违规案例（本次教训）：
- ❌ 把"自主设置的二级学科，隶属于XXX一级学科（代码XXX）"改写成"自主设置二级学科（代码XXXX），隶属于应用经济学一级学科（代码XXXX）"——擅自改模板措辞、加了模板没有的字段
- ❌ 标题"关于XXX专业一致性的说明"的"XXX"→"申请人同志"（加"同志"）——只应替换占位符，不增删模板字
- ✅ 正确做法：模板写"隶属于XXX一级学科（代码XXX）"就只填"应用经济学一级学科（代码XXXX）"，模板没要求填二级学科代码就别塞具体代码；模板写"XX学院"就填"数学与统计学院"，不加"同志/学院"等多余字

**替换原则**：每个占位符只替换为最小必要的真实值；信息在模板里没有对应占位符时，告诉用户"模板没有该字段位置"而不是改模板硬塞。替换完成后读回验证——模板原文文字（非占位符部分）应逐字不变。

## 完整流程

### 步骤1：读取模板（按格式分流）

**docx（最常见）** = zip 压缩包，直接解 XML 读文本：
```python
import zipfile, xml.etree.ElementTree as ET
with zipfile.ZipFile(path) as z:
    xml = z.read("word/document.xml").decode("utf-8")
# 提取段落文本（遍历 <w:p> 内所有 <w:t> 拼接）
```

**旧 .doc（非 zip）** = OLE 二进制，直接 `decode("utf-16-le", errors="ignore")` 提取中文，正则捞关键信息：
```python
text = open(path, "rb").read().decode("utf-16-le", errors="ignore")
id_matches = re.findall(r'\d{17}[\dXx]', text)   # 18位身份证
# 用关键词（岗位/专业/代码/学院）定位上下文段落
```

**扫描版 PDF（无文本层）** = PyMuPDF 导出 PNG 再 OCR：
```python
import fitz, os
doc = fitz.open(path)
for i, page in enumerate(doc):
    pix = page.get_pixmap(dpi=150)
    out = os.path.join(os.environ["TEMP"], f"page{i+1}.png")  # 必须 Windows 原生路径！
    pix.save(out)  # 然后逐个 vision_analyze 读
```

### 步骤2：从信源收集字段

优先级：**官方证明材料（专业证明/学位证明，最权威）** > 招聘考核表/报名表 > 求职简历 > 基本信息.pdf > 学号推断。

- **身份字段**：姓名/性别/身份证号/出生年——简历和考核表都有，考核表 .doc 里用 UTF-16 正则直接捞
- **学历字段**：博士院校/专业/起止时间——简历教育背景表
- **学科归属**：优先找**官方专业证明材料**（2026.8.5 实测：`专业证明材料.pdf` 由某高校数学学院出具，写明"应用经济学（代码XXXX）下的自设二级学科数理金融学（代码XXXX）"——比学号推断权威）。**学号可推断专业代码**（某高校学号 `学号XXXXXXXXXXX` → 应用经济学一级学科；学号中 `Z` = 自设学科）
- **岗位字段**：招聘考核表"应聘学院及岗位"栏（如"数学与统计学院，专任教师"）
- **主修课程**：⚠️ **不能从简历"可授课程"栏抄**——那是本科/教学课程（如概率论与数理统计），不是博士主修课程。必须问用户或从博士成绩单提取（2026.8.5 教训：用户纠正"数理与统计是本科的课程"，改为高级宏观经济学/高级微观经济学/高级计量经济学/高级数理金融学）

### 步骤3：占位符替换（⭐ 核心坑）

**坑：模板占位符文本会被 Word 拆散在多个 `<w:t>` run 里**——"XXX 大学"可能跨 2-3 个 run（`XXX` 在 run1、` 大学` 在 run2）。此时：
- ❌ 在单个 `<w:t>` 标签内做正则替换 → 匹配失败（"未找到"）
- ❌ 正则限制 `<w:t[^>]*>` → 带属性的标签（`xml:space="preserve"`）匹配不到
- ✅ **在整段 XML 字符串上做全局 `xml.replace()`**：占位符文本（如 `20XX 年 XX 月至 20XX 年 XX 月`）在文档中唯一，全局替换不会误伤。实测一次清空全部占位符

```python
replacements = [
    ("XXX（男 / 女，身份证号：XXXXXXXXXX）", "申请人（男，身份证号：身份证号XXXXXXXXXX）"),
    ("20XX 年 XX 月至 20XX 年 XX 月", "在读期间"),
    # ... 全部占位符 → 真实值
]
for old, new in replacements:
    if old in xml:
        xml = xml.replace(old, new)   # 全局替换，不限于 w:t 内
# 替换完成后 zipfile 写回新 docx（保留原文件所有 zip 条目，只换 document.xml）
```

### 步骤4：冲突字段用 clarify 确认（不猜）

信源间字段冲突时（2026.8.5 实测：考核表写"数学与统计学院"，桌面文件夹写"经济与管理学院"）——**必须 clarify 问用户**，不要自行选择。事后发现：经济与管理学院是用户当年应聘原单位的旧文件夹，现单位岗位是数学与统计学院。带选项问，用户秒答。

### 步骤5：验证（必做）

替换后**读回新 docx 提取全文**，检查：
- `XX` 残留 = 0（正则 `XX+` 扫 XML）
- 关键字段值正确（姓名/身份证/学院/岗位）
- 把最终全文展示给用户核对（重点标出留空的日期/待盖章项）

## 常见陷阱

1. **f-string 内不能有反斜杠正则**（Python 3.11）：`print(f"...{len(re.findall(r'\d', x))}...")` 报 SyntaxError。正则先编译成变量再引用。
2. **Python 不认 MSYS 路径**：`/c/Users/...`、`/tmp/...` 在 Python 里报 "No such file or directory"。用 Windows 原生路径（`C:\...`）或 `os.path.join(os.environ["TEMP"], ...)`。Shell 命令里用 MSYS 路径，Python 代码里用 Windows 路径。
3. **OCR 连接错误**：vision_analyze 偶发 Connection error——重试即可，或分页处理。
4. **模板正文与截图版本有出入**：docx 里的占位符空格/标点可能与截图显示不同（如"XXX（男 / 女，身份证号：XXXXXXXXXX）"中间有空格）。以 **docx 实际 XML 文本为准**（读出来的为准），不要照截图文字替换。
5. **套红头/盖章留空**：文档交给用户后他还要套学院红头、盖公章、填日期——交付时明确列出这些"用户手动步骤"，日期留 `2026年 月 日` 空位。
6. **不要重复问已能从信源提取的信息**：身份证号/性别/院校等先从简历和考核表提取，只有真正缺失或冲突的字段才问。
