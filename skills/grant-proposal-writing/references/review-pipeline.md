# 多Agent评审流水线详细配置

> 来源：2026.8.12-8.14 省自科基金申报书写作实战经验

## 流水线架构

```
丞相初稿 → Codex评审 → 丞相修改 → Claude Code评审（含修改原因） → 丞相修改 → 丞相终审 → 少帅审阅
```

## 各环节配置

### 1. 丞相初稿
- 模型：当前主模型
- 依据：申报书框架V2/模板规则
- 产出：Markdown源文件

### 2. Codex评审
- 命令：`node codex.js exec --skip-git-repo-check "任务"`
- **必须前台运行**（background=true必报stdin is not a tty）
- 输出重定向到output目录后cat读取
- 评审视角：评委（10-20分钟/份，扫描式阅读）
- 产出：评审意见（含P0致命问题+P1高优+P2中优）

### 3. Claude Code评审
- 命令：`claude -p --permission-mode auto "任务"`（需ANTHROPIC_BASE_URL+代理）
- **须带修改原因说明**——告诉它为什么这么改，让它在信息全面情况下评审
- 可后台运行（比Codex稳定）
- 产出：评审意见（逐条分级）

### 4. 丞相终审
- 逐条处理两方评审意见：采纳/澄清/不采纳
- **事实性主张须查证**（如"环保税申报表含销售额字段"→查证A表实际字段）
- 产出：最终版（含修复说明）

## 派发前必做

1. **写无歧义书面表述**（少帅原话："你一定先表达清楚再给它们两"）
2. 包含：背景（为什么改）+ 具体评审维度 + 评分标准
3. 验证文件可读性（read_file测试路径）

## 失败降级

- Codex后台报错 → 前台重跑
- Codex超时（后端不稳） → 跳过，用Claude Code+丞相两方汇总
- Claude Code 429/500 → 等1分钟重试；连续失败则暂停

## 评审意见处理模板

```markdown
| # | agent发现 | 采纳？ | 丞相判断 | 修改方案 |
|---|----------|:---:|---------|---------|
| 1 | xxx | ✅/❌ | 采纳原因/不采纳原因 | 具体修改 |
```
