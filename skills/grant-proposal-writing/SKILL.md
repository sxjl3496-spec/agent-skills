# 省自科基金申报书写作

## 触发条件

用户要求写/改/评审省自科基金申报书时触发。适用于：湖南省自然科学基金、国家自然科学基金地区项目、省级联合基金等。

与 `academic-paper-composer`（论文写作）和 `research-writing-skill`（论文润色）不同——申报书有**固定提纲**、**特定评审标准**、**评委时间约束**（10-20分钟/份）。

## ⚠️ 核心原则（用户反复强调）

1. **评委可读性是第一原则**：标题术语堆叠是大忌，评委3秒看不懂就放弃——宁可降门槛，不可炫术语
2. **丞相是最终质量把控者**：不能当甩手掌柜只做任务分发，必须亲自通读、亲自把关
3. **多agent评审流水线**：Codex→Claude Code→丞相终审，两者均允许大改
4. **"排除替代路径"是最强武器**：预堵"为何不用更主流方案"的质疑

## 提纲结构（从23张模板截图提炼）

湖南省自科基金申报书提纲（五模块，**提纲标题不可删改**）：

```
(一) 立项依据与研究内容（建议8000字以内）
  1. 项目的立项依据
    1.1 研究意义（科学意义 + 应用前景，各3点）
    1.2 国内外研究现状及发展动态分析
      1.2.1 主题A研究
      1.2.2 主题B研究
      1.2.3 主题C研究
    1.3 科学意义或应用前景（湖南版式后置位）
  2. 项目的研究内容、研究目标，以及拟解决的关键科学问题（重点阐述）
    2.1 研究内容（3大块递进链）
    2.2 研究目标（核心1句 + 具体3条）
    2.3 拟解决的关键科学问题（3个问句）
  3. 拟采取的研究方案及可行性分析
    3.1 研究方法
    3.2 技术路线
    3.3 实验手段
    3.4 关键技术
    3.5 可行性分析（四维：理论/数据/技术/条件）
  4. 本项目的特色与创新之处（四创新）
  5. 年度研究计划及预期研究结果
    5.1 年度研究计划（3年）
    5.2 预期研究结果
    5.3 拟组织的重要学术交流活动、国际合作与交流计划
(二) 研究基础与工作条件
(三) 经费预算
```

> ⚠️ **湖南版式特有差异**：科学意义/应用前景在1.3位置（背景漏斗之后），不在立项依据开头——不能照抄国家自科版式。

## 写作技巧（跨领域可复用）

### 立项依据"漏斗式"5段
1. **宏观背景**：大背景 + 中国定位
2. **数据震撼**：首段必放硬数据（绝对数 + 占比双管齐下）
3. **现状不足**：现有研究缺口
4. **切入视角**：本研究视角（时间区间 + 对象 + 方法）
5. **理论框架预告**：提出分析框架 + 配框架图

### 文献综述"双层漏斗"
1. **主题小节**（按主题分，非按时间）：每个小节 = 研究脉络（作者+年份+观点）+ 该主题1-2句"局限"收尾
2. **独立评述段**：3条编号不足 + 一句结论（本研究价值）

### ⭐ 三处强对齐闭环（区分一般稿与高分稿的核心）
综述的3条不足 ↔ 研究内容3大块 ↔ 关键科学问题3问，**必须一一映射**

### 标题即结论
所有小标题用名词性短语，含"对象 + 维度 + 动作"（如"绿色技术创新及细分领域的时空演化特征解析"），评审扫标题即判断内容完整性

### 创新点四创新模板
1. 研究视角创新（突破XX局限，从XX切入）
2. 理论框架创新（构建XX框架，修正西方假设，嵌入本土要素）
3. 研究设计创新（多阶段动态演化）
4. 应用策略创新（分层分类差异化路径）

### 年度计划"任务+产出"双线
每年 = 任务 + 当年论文/会议数（不可只写任务）

### 预期成果可考核性
论文要给期刊档次和篇数、报告要给名称、人才要给人数——避免"发表高质量论文若干"式空话

## 多Agent评审流水线

```
初稿（丞相写作）
  ↓
Codex评审（评委视角，允许大改）
  ↓ 丞相按点评修改
Claude Code评审（评委视角，允许大改，含修改原因说明）
  ↓ 丞相按点评修改
丞相终审（两层验证 + 硬验证）
  ↓
交付少帅
```

关键要求：
- 派发agent前必须**无歧义书面表述**（少帅："你一定先表达清楚再给它们两"）
- Claude Code审核须**带修改原因说明**（"告诉Claude Code为什么这么修改的原因"）
- 丞相是**最终质量把控者**（"你不能当甩手掌柜"）
- 每个agent评审意见须逐条分类：采纳/澄清/不采纳（附理由）

## 数学公式Word化（pandoc路径）

申报书含数学公式时，优先Word格式（少帅偏好），用 **Markdown + LaTeX公式 → pandoc → Word(OMML)** 路径：

```bash
pandoc 申报书.md -o 申报书.docx
```

验证公式转换：
```python
import zipfile, re
z = zipfile.ZipFile('申报书.docx')
xml = z.read('word/document.xml').decode('utf-8')
omml_count = xml.count('m:oMath')  # OMML公式数
tex_remains = re.findall(r'\\\\[a-zA-Z]+', xml)  # TeX残留应为空
```

已知陷阱：
- `cases` 环境在docx中渲染为TeX源码 → 改用 indicator function `1{条件}` 替代
- `printf` 中 `\\frac` 被吃掉 → 用 `write_file` 写md文件，不用 `printf`/`echo`

## 评委视角清单

**评审真实行为**：前5分钟扫标题→摘要→创新点→科学问题→研究内容标题→年度计划，每屏约30秒；**给分决策发生在3-5分钟内**。

1. 第一屏定生死：首段2-3句含"问题 + 数据 + 后果" + "为何必须现在解决"
2. 数学/CS评委盯：偏差是否承认处理、模型是否真实数据校准、公式量纲自洽
3. 管理评委盯落地：数据跨部门可用性、行政可执行性
4. "排除替代路径"提到明显位置
5. 科学问题问句化（一问 + 3子问）
6. 湖南元素贯穿全篇（机构名/文号/三层路径）
7. 年度计划第1年必须有"数据可得性验证/预实验"里程碑
8. 每屏可独立阅读（标题即结论、关键句加粗、公式编号一致）
9. 参考文献自查：近5年≥60%、中英搭配、编号与正文引用对应
10. 数字全篇自查：数据前后一致、量化预期区间表述

## 常见陷阱

### 陷阱1：标题术语堆叠
"激励相容""法定税收数据""差异化定价"——评委看不懂就放弃。Claude Code和Codex已验证：3秒可懂 > 术语精准。
**修复**：标题降门槛（如"政策仿真"替代"反事实仿真"），术语放正文首次出现时加注。

### 陷阱2：文献综述与研究内容脱节
综述写了3个脉络，但没有与研究内容、科学问题形成映射——评委觉得"各写各的"。
**修复**：综述3条不足 → 研究内容3大块 → 科学问题3问，严格一一对应。

### 陷阱3：Codex后台运行报错
Codex CLI在后台（`&`）运行时必报 `exit=1 (stdin is not a tty)`。
**修复**：Codex必须**前台运行**（不用`&`或`background=true`），用 `timeout` 管理超时。

### 陷阱4：模型名称误选导致评委质疑
"效率定价"被环境经济评委误读为"最优庇古定价"；"回购"与机制矛盾。
**修复**：每个术语写完后自查——"非专业评委第一反应是什么？会不会误解？"

### 陷阱5：事实性主张被推翻
"环保税申报表含销售额字段"经查证不实——A表主表无销售额，但附表有产品产量。
**修复**：所有事实性主张（特别是制度/表格/数据字段）须查证原文，不可凭推断写入。

### 陷阱6：环保税达标减征干扰A测度
$r_i$ 与减排行为相关 → 系统性偏差。
**修复**：用"未折扣计税基础"（标准税额重构）+ ABM设系统偏差臂检验。
