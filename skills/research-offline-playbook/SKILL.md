# 离线调研报告执行 Playbook

## 概述

在无法使用 Web 搜索的环境中，本 Playbook 提供一套**分级降级策略**，确保调研任务仍然能产出结构化的分析报告。核心原则：**绝不编造引用数据**，每一步明确标注信息来源的可信度等级。

---

## 信息可信度等级体系

| 等级 | 来源类型 | 说明 |
|------|---------|------|
| **A级** | 在线来源 / 同行评审期刊 / 权威机构官方数据 | 最高可信度，可直接引用 |
| **B级** | 用户本地提供的 PDF/CAJ文件 / 已同步的本地文档库 | 中等可信度，需核实出版来源和日期 |
| **C级** | Session历史中已积累的笔记和分析结果 | 情境依赖，需确认与当前任务的相关性 |
| **D级** | 模型专家知识 + 合理推断（非具体引用） | 最低可信度，必须标注为"基于领域经验推断" |

**硬性规则**：
- 报告中每个观点/数据点都应标注其可信度等级（A/B/C/D）。
- D级内容可以存在，但必须用不同措辞区分——如"根据我对XX行业的理解……"而非"据XX报告显示……"。
- **绝不允许编造具体的论文标题、作者、发表年份或数据来源。**

---

## 降级链（按优先级顺序执行）

### 层级0：网络可用性探测

**第一步**：尝试一个轻量级的网络请求来判定是否真正不可达。

```bash
# 方法1：duckduckgo HTML搜索（通常权重较低，不会占用过多带宽）
curl -sL 'https://html.duckduckgo.com/html/?q=<关键词>' | sed 's/<[^>]*>//g' | head -50
```

**判定标准**：
- 如果返回了非空文本 → 进入正常在线搜索模式
- 如果返回空字符串或连接超时 → **立即停止所有网络尝试**，进入层级1

**重要**：只尝试一次即可，不要反复重试浪费时间和注意力。如果 DuckDuckGo 失败，就认定网络不可用。

---

### 层级1：本地文件系统搜索

搜索用户的本地文件目录，寻找相关素材：

```python
# 搜索关键词相关的文件和目录
search_files(pattern="*行业*", target="files", path="<知识库根目录>")
search_files(pattern="*报告*", target="files", path="<知识库根目录>")
```

**搜索路径优先级**：
1. `<知识库根目录>/` — 主同步盘，最大的本地资料库
2. `~/.hermes/` 或 `hermes-data/` 下的缓存、笔记、技能文件
3. `Obsidian Vault` 或其他笔记应用的数据目录
4. 用户当前工作目录

**注意 Windows 环境**：
- Git Bash 下使用 `<知识库根目录>/...` 路径格式
- 也可以使用完整的 `C:\Users\<用户名>\...` 路径
- `read_file()` 自动支持 `.ipynb`, `.docx`, `.xlsx` 格式的文件读取

---

### 层级2：PDF/CAJ文档内容提取

发现相关 PDF 后，逐页提取文本：

```python
import fitz  # pymupdf

doc = fitz.open(r'D:/path/to/file.pdf')
for i, page in enumerate(doc):
    text = page.get_text()
    print(f'--- Page {i+1} ---')
    print(text[:2000])
```

**关键注意点**：
- 使用完整绝对路径（带 `r` 前缀防止转义问题）
- 如果页面有嵌入图片，`page.get_images()` 非空时需用视觉 API 识别
- CAJ 格式不是 PDF，`fitz` 无法直接读取；如遇 CAJ 格式，记录该限制并在最终报告中注明
- read_file() 工具也能读取 .pdf 但不能解码二进制内容，优先用 fitz

---

### 层级3：Session 历史检索

查找过去会话中的相关讨论和已积累的资料：

```python
session_search(query="某行业 政策 发展现状", limit=5)
```

**使用场景**：
- 用户之前做过相同主题的调研并留下了笔记
- 对话中有用户上传过相关资料
- 之前的分析结论可能有参考价值

---

### 层级4：专家知识合成

当以上层级都无法找到足够资料时，进入此层：

**正确做法**：
1. **先总结已有资料的发现**（从层级1-3获得的内容）
2. **然后以领域专家身份补充背景信息**
3. **明确标注哪些是已知资料支撑，哪些是推断**

```markdown
## X. 基于领域知识的补充分析

**来源**: D级 — 基于对XX领域的理解进行推论，未经直接文献验证。

### X.1 XXXX
根据对该领域的一般认知，XX省的情况可能包括……（此处列出可能的情况）

⚠️ 注意：以上分析未找到直接文献支撑，建议后续通过在线渠道补充验证。
```

---

### 层级5：输出结构化报告

无论到达哪个层级，都要产出完整、结构清晰的报告。

**报告模板**：

```markdown
# [主题] 调研报告

## 摘要
[简要概括，标明整体资料来源等级]

## 一、背景与现状
[来自最可靠层级的信息]

## 二、存在的问题与不足
[混合B级和D级内容时需明确标注]

## 三、可切入的研究空间
[结合已有资料和领域知识提出方向]

## 四、结论与建议

## 参考文献
[仅列出确知的文献。D级内容不在正式参考文献列表中出现，而是在正文中用"【D级-专家推断】"标注]
```

**强制步骤**：报告必须写入持久化文件，方便后续迭代和参考。

## 决策流程图

```
开始调研任务
    ↓
层级0: curl web搜索测试
    ├─ 成功 → 正常在线搜索流程
    └─ 失败 → 层级1
         
层级1: 本地文件搜索 (search_files)
    ├─ 找到相关文件 → 层级2
    └─ 未找到 → 层级3
        
层级2: PDF内容提取 (fitz/read_file)
    ├─ 提取到有价值内容 → 汇总资料进入层级5
    └─ 内容不足 → 层级3
    
层级3: Session检索 (session_search)
    ├─ 找到相关内容 → 汇总资料进入层级5
    └─ 未找到 → 层级4
    
层级4: 专家知识合成
    ├─ 构建结构化分析
    ├─ 每部分内容标注可信度等级
    └─ 进入层级5
    
层级5: 输出报告 + write_file
```

## 常见陷阱

1. **不要反复重试网络请求**：一次失败的探测就够了，反复尝试只会增加等待时间。
2. **不要把 fitz 导入进 shell 命令管道**：Python 脚本应完整写出（可以用 write_file 临时创建脚本再运行）。
3. **Windows 路径问题**：Git Bash 下 `\` 会被转义，始终用 `r'...'` 原始字符串或正斜杠 `/`。
4. **大文件 PDF 不必全读**：先看总页数和摘要/引言就能掌握大部分内容，除非需要全文细节。
5. **CAJ 格式是中国知网专用格式**：`fitz` 不支持，需要转换为 PDF 或用知阅读客户端打开。
6. **网络不可用时不要用 AI 编造数据**：宁可写"暂未找到确切数据"，也不要编造数字。
