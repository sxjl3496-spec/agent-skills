# 项目上下文持久化 (project-context)

## 何时使用

- 复杂任务执行中，需要持久化当前进度
- 会话即将结束（模型限额、需重启）需保存状态
- 新会话开始时，需要恢复之前的任务上下文
- 用户问"我们做到哪了"

## 工作机制

### 状态文件

在工作目录下维护 `.hermes/project-state.md`：

```markdown
# Project State

## 当前任务
- 任务名称：xxx
- 开始时间：2026-07-30
- 状态：进行中/暂停/完成

## 进度
- [x] 步骤1：xxx
- [x] 步骤2：xxx
- [ ] 步骤3：xxx（当前）
- [ ] 步骤4：xxx

## 决策记录
- 2026-07-30: 选择方案A而非B，原因是xxx
- 2026-07-30: 降级到 deepseek-v4-flash，因为 Coding Plan 限额

## 待办
- 验证 xxx 配置
- 重启 gateway 使 xxx 生效

## 关键文件
- config: D:\...\config.yaml
- 输出: D:\...\output\

## 环境状态
- gateway: 运行中/需重启
- 模型: glm-5.2 (volcano)
- 代理: Clash <代理端口>
```

### 保存时机

1. **任务中途**：完成一个关键步骤后保存
2. **会话结束前**：检测到可能中断（限额、超时）时保存
3. **用户要求**：用户说"保存进度"时
4. **中断恢复**：中断后恢复时先读取状态

### 恢复流程

1. 检查工作目录下 `.hermes/project-state.md` 是否存在
2. 读取状态文件，了解任务进度
3. 用 read_file/terminal 验证状态文件中记录的文件/配置实际状态
4. 从断点继续

## 使用方式

### 保存状态
```
保存当前进度到 project-state.md
```

### 恢复状态
```
读取项目状态，告诉我上次做到哪了
```

### 更新进度
```
更新项目状态：步骤3已完成
```

## 注意事项

- 状态文件是 Markdown，不要用 JSON（可读性差）
- 每次保存覆盖旧内容，不追加（避免文件膨胀）
- 决策记录只保留最近10条，旧的删除
- 关键文件路径用绝对路径
- 如果工作目录不可写（如D盘需管理员），尝试写到 ~/AppData/Local/hermes/project-state.md
