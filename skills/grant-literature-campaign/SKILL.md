# 基金申报文献战役 (Grant Literature Campaign)

## 何时使用

- 用户说"文献清单在知识库里你找一下"、"文献有重复先去重分类"、"详细阅读文献写好解读要点"、"根据解读文档撰写申报书文献综述部分"、"做好要给XX审核"
- 已有下载好的 PDF 文献库（如 ObsidianVault/academia/文献库/<主题>/）+ 文献清单（txt/md），需要端到端加工成综述
- 与 literature-review 技能互补：literature-review 管"从零检索生成综述"，本技能管"已存在语料的分拣精读与综述写作"；与 aionui-team-leadership 互补：本技能管文献战役的业务流程，团队协作细节看那个技能

## 战役流程（九步）

1. **清点资产**：先找清单（常在 ObsidianVault/academia/ 下，命名如 `*申报书*文献清单*.txt`），再列 PDF 库目录。用 execute_code 脚本交叉核对"清单条目 vs PDF 文件名"，标出：清单有而PDF缺、PDF有而清单缺（清单外文献）、文件名带 `(1)` 的重复副本
2. **去重**：清单内部重复（同一文献重复编号，如 [55]=[78]）按**标题归一化匹配**检出——编号跳跃本身就是重复信号（如清单 [1]-[80]+[91]-[98]，缺号段里藏着重复）；PDF 目录 `(1)` 后缀文件去重。以标题为唯一键，不以编号
3. **分类+期刊级别标注**：按申报书机制要素分主题类（典型：制度政策/定价机制/市场运行/仿真方法/环境税/效率测度/协同治理/英文文献）；标注 CSSCI/北核/非CSSCI（用户清单常已标注非CSSCI，注意个别未标但期刊明显非核心的）；**引用红线：只引CSSCI，北核特别重要才引，非CSSCI仅作背景了解**
4. **设计解读模板**（9维度）：研究背景 / 研究问题 / 方法 / 数据 / 主要发现 / 局限 / 与本课题相关性评分(1-5) / 可引用点 / 期刊级别
5. **并行精读分配**：相关度判定按机制要素排序——机制设计（定价公式/奖惩函数）> 方法（ABM/仿真平台）> 数据（环保税/税收数据）> 政策背景（试点/协同）> 泛效率测度。相关性最强批次（≤20篇）lead 亲自精读；其余按能力矩阵分给队友各领一类。子agent并行（delegate_task）先测可用性，不可用则"lead亲办+队友分批"已覆盖
6. **英文文献处理**：⚠️ 高频陷阱——"只有清单无PDF"（历史会话整理的英文推荐清单可能躺在 hermes-data/output/申报书/文献探讨_*.md 里）。先 Crossref 反查待核实条目，尽力下载 OA/DOI 直取；无法下载则基于摘要+核实元数据解读并**如实标注"未读全文"**，绝不假装已读。向用户如实报告英文PDF缺失状态
7. **汇总解读文档**：按分类组织（每篇：要点+相关性评分），末尾专设"研究空白挖掘"节——对照本课题机制设计找缺口（如"定价机制文献多为定性/经验，缺乏机制设计与ABM仿真结合"），这是突出课题研究意义的弹药
8. **撰写综述**：基于解读文档写申报书文献综述部分，GB/T 7714 格式；参考文献必须 Crossref/PDF 双重验证（零编造/零残缺/零"待核实"——省自科战役红线）
9. **双agent审核**：解读文档与综述交两位独立 agent 审核（覆盖度/相关性/真实性/格式），lead 综合意见终审修订——lead 是最终质量把控者，亲自通读后独立评分，不只转述

## 常见陷阱

1. **清单编号跳跃 ≠ 缺文献**：可能是补录段（如 [91]-[98]），也可能是重复的替身——以标题为键，别按编号顺序盲目对账
2. **PDF库有清单外文献**：可能是用户自己的论文（→作"研究基础"写入综述，不列为引用文献）、或补充的北核文献（→按红线决定是否引用）——逐篇判断，不要一律忽略或一律纳入
3. **英文文献待核实条目**（如 Zhang&Choi 2014 / Perino et al. 2022 类）：Crossref 反查卷期页码，反查不到就标注，不编造
4. **非CSSCI标注不完整**：用户标注了大部分，个别期刊（如《管理学家》《皮革制作与环保科技》）明显非核心但未标——按期刊常识补标，并如实告知用户
5. **/plan 入口必须走 plan 流程**：少帅对此类大任务常用 /plan 下发，第一行必须输出 `## 表达优化` 三段式，输出执行计划等确认，不可直接开干
